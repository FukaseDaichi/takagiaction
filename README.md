# TAKAGI ACTION

[phoboslab/underrun](https://github.com/phoboslab/underrun)（js13kgames 2018 出品作 **UNDERRUN**）をベースに、日本語向けにアレンジしていくプロジェクトです。

見下ろし型（トップダウン）のアクションシューティング。プレイヤーは施設に送り込まれた端末となり、オフラインになった各フロアのシステムを再起動して回ります。WebGL 製で、オリジナルはゲーム本体・グラフィック・BGM をすべて含めて **13KB 以下**という制約の中で作られています。

## ローカルでの起動

PNG 画像をテクスチャとして読み込むため、`file://` で直接開くと動きません。簡易 HTTP サーバー経由で開いてください。

```bash
uv run python -m http.server 8000
```

サーバーを起動したら、ブラウザで `http://localhost:8000/` を開きます。ビルドは不要で、`source/` 以下のファイルをそのまま読み込みます（編集したらリロードするだけで反映されます）。

起動するとターミナル風のイントロが流れます。**画面をクリックするとゲーム開始**です（音声再生のためにクリックが必要です）。

推奨環境: WebGL と Web Audio API に対応した最近のブラウザ（Chrome / Firefox / Safari / Edge）。

## 操作方法

| 操作 | キー / 入力 |
| --- | --- |
| 移動 | `W` `A` `S` `D` または `↑` `←` `↓` `→` |
| 射撃 | `スペース`（押しっぱなしで連射／約 0.1 秒間隔 = 毎秒 10 発） |
| 音声 ON / OFF | `M` |
| ゲーム開始 | 画面をクリック |

- 自機は 8 方向のスプライトで**進行方向**を向きます。
- `スペース` を**押している間は向きが固定**されます（射撃モード）。押したまま移動すれば、向きを保ったままの後退射撃やストレイフができます。離すと再び進行方向を向きます。移動していない間は最後の向きを維持します。
- 弾（プラズマ）は壁に当たると消えます。連射は押しっぱなしで OK です。
- 音声（BGM・効果音）は `M` で一括切り替えできます。GitHub Pages などでは既定 ON、`localhost` / `127.0.0.1` / `file://` での開発時は既定 OFF です。設定は保存されないので、リロードすると既定値に戻ります。

## ゲームのルール

### 目的

各フロアには**オフラインになった CPU 端末**が配置されています。端末に**触れる**と再起動（REBOOT）が実行されます。

1. フロア開始時に「`停止中のシステムを走査中...` / `N 件のシステムを検出`」と対象数が表示されます
2. 端末に触れるたびに残り台数が表示されます
3. **そのフロアの端末をすべて再起動すると次のフロアへジャンプ**します
4. 全 **3 フロア**。3 フロア目をクリアするとエンディング（送信メッセージ）が流れます

### 体力とミス

| 項目 | 内容 |
| --- | --- |
| 最大 HP | 5（画面左下にゲージ表示） |
| ダメージ | スパイダーの接触で 1、セントリーのプラズマ弾で 1 |
| 無敵時間 | 被弾後 2 秒間（自機が点滅します） |
| HP 0 のとき | `展開失敗` → 3 秒後に**同じフロアの最初からやり直し** |
| リトライ回数 | 無制限（スコア・残機の概念はありません） |

フロアの地形は**フロア番号から決まる固定シード**で生成されるため、やり直しても敵やアイテムの配置は毎回同じです。ルートを覚えれば有利に進められます。

### マップ（画面右上）

画面右上に**フロア全体のマップ**が常時表示されます。最初はすべて未探索の暗闇で、進むにつれて見えた範囲だけが描き込まれていきます。

| 表示 | 意味 |
| --- | --- |
| 暗いティール | 探索済みの床 |
| 明るいグレーブルー | 探索済みの壁 |
| 明るい青 | CPU 端末（停止中） |
| 暗い青 | CPU 端末（再起動済み） |
| 白 + 橙の点 | 自機の位置と向き |
| 何も描かれない | 未探索 |

- 開示判定は**視線ベース**です。自機から半径 10 タイル内にレイを飛ばし、**壁で遮られた先は未探索のまま**残ります。通路の奥や角の向こうは、実際にそこまで進まないと見えません。
- **未探索エリアにある CPU 端末はマップに出ません。** 端末を探す作業そのものは省略されず、一度見つけた端末の場所を忘れずに済む、という位置づけです。
- マップは**フロアごとにリセット**されます。ミスして同じフロアをやり直した場合も白紙に戻ります（敵やアイテムの配置もリセットされるため）。
- エンディング中は非表示になります。

### 敵

| 敵 | 耐久 | 行動 |
| --- | --- | --- |
| **スパイダー**（蜘蛛型） | プラズマ 5 発 | 距離 64 以内に入るとプレイヤーを追尾。接触すると 1 ダメージを与えて弾かれる。撃破すると爆発 |
| **セントリー**（砲台型） | プラズマ 20 発 | 距離 64 以内で接近開始、48 以内でプラズマ弾を発射、24 以内まで近づくと停止して撃ち続ける。硬いので正面から撃ち合うと不利 |

- スパイダーはフロアが進むほど出現密度が上がります（床タイルあたり約 1/15 → 1/13 → 1/11）。
- フロア開始時、プレイヤーのスタート地点の近く（距離 64 以内）にいるスパイダーは取り除かれます。

### アイテム

| アイテム | 効果 |
| --- | --- |
| **ヘルスパック** | HP +1（最大 5 まで。HP 満タンのときは回復しません） |

床タイルあたり約 1/101 の確率でランダムに配置されます。HP が減るまで取らずに温存しておくのがコツです。

### 攻略のヒント

- セントリーは射程 48 で撃ってきます。**壁を盾にして角から撃つ**と被弾を減らせます。
- スパイダーは接触ダメージのみ。敵に向いた状態で `スペース` を押し、**向きを固定したまま後退しながら撃つ**と安全に処理できます。
- 端末はどの順番で再起動しても構いません。詰まったら**敵の少ないルートから端末を回収**しましょう。
- HP が 1 になったら無理をせず、ヘルスパックの場所まで戻るのも有効です。

## レベルデータの仕組み

レベルは `m/l1.png` 〜 `m/l3.png` の **64×64 ピクセルの PNG 画像**で定義されています。ピクセルの色がそのままオブジェクトの種類になります（12bit カラーに丸めて判定）。

| 色 | 意味 |
| --- | --- |
| `#000000`（黒） | 何もない空間（ボイド） |
| `#888888`（グレー） | 壁 |
| `#00FF00`（緑） | プレイヤーのスタート位置 |
| `#0000FF`（青） | CPU 端末（再起動対象） |
| `#FF0000`（赤） | セントリー |
| 上記以外の色 | 床 |

床タイルの上にスパイダーとヘルスパックが確率でランダム配置されます。**新しいフロアを作りたい場合は、この規則で PNG を描いて `m/` に追加**し、`source/game.js` のフロア数（`next_level` の判定）を増やしてください。

## ディレクトリ構成

| パス | 内容 |
| --- | --- |
| `index.html` | エントリーポイント。各ソースを個別に読み込むので、ビルドなしで動作します（GitHub Pages もこれを配信） |
| `.nojekyll` | GitHub Pages で Jekyll の処理を無効化するためのマーカー |
| `source/` | ゲーム本体のソース一式 |
| `source/game.js` | 入力処理、レベル読み込み、メインループ |
| `source/renderer.js` | WebGL レンダラー（320×180 のピクセルアート描画、ライティング） |
| `source/entity*.js` | プレイヤー・敵・弾・アイテムなど各エンティティ |
| `source/minimap.js` | 画面右上のマップ（視線判定によるフォグオブウォー、2D canvas で描画） |
| `source/terminal.js` | ターミナル風の演出とテキスト（イントロ / ストーリー / エンディング） |
| `source/audio.js`, `sound-effects.js`, `music-*.js` | 効果音と BGM（Sonant-X で実行時に生成） |
| `source/html-template.html` | 配布用 HTML のテンプレート |
| `m/` | 画像。`q2.png` がスプライトのアトラス、`l1〜l3.png` がレベルデータ |
| `build.sh` | 結合 → 圧縮 → zip までを行うビルドスクリプト |
| `shrinkit.js` | ソースを縮めるための独自の前処理スクリプト |

## ビルド

```bash
npm install
```

```bash
./build.sh
```

`build/` 以下に、単一ファイル版の `underrun.html` と、js13k 提出用の `underrun.zip` が出力されます。

> **メモ**: `build.sh` は先頭で既存の zip を `rm` するため、初回実行時は「そんなファイルはない」というエラーが 1 行出ますが、処理自体は問題なく進みます。

## 日本語アレンジのメモ

- **テキストの日本語化**: 完了。画面に出る文言は `source/terminal.js`（イントロ / ストーリー / エンディング）、`source/game.js`（フロア開始時の走査メッセージ）、`source/entity-cpu.js`（再起動メッセージ）、`source/entity-player.js`（`展開失敗`）、`source/main.js`（`起動中...`）にあります
  - 作者名・URL・`JS13K` などの固有名詞と、`CPU: PL(R) Q-COATL 7240 @ 12.6 THZ` のような疑似スペックはそのまま残しています
  - ターミナル演出では `_` が改行 10 個（= 約 1 秒の待ち）に展開されるため、**文中に `_` を書かないこと**（`terminal_prepare_text` を参照）
- **タイトルまわり**: 完了。`index.html` と `source/html-template.html` の `<title>` を `TAKAGI ACTION` に変更済み
- **表示スタイルの調整**: 現状は不要。ターミナル表示（`#a`）は `white-space: nowrap` の 1 行表示・等幅前提ですが、日本語の各行は最長でも横幅の約半分で収まっているため折り返しは発生しません。今後長い行を足す場合は要注意
- **レベルの追加・難易度調整**: 上記「レベルデータの仕組み」を参照
- **ファイルサイズの制約について**: 13KB は js13k のルールなので、このリポジトリでは必ずしも守る必要はありません。日本語テキストはバイト数が増えるため、サイズを気にせず自由にアレンジできます
