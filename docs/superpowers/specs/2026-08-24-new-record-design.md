# 最高深度スコアの可視化とニューレコード演出

## 目的

TAKAGI ACTION は最高到達深度を伸ばすことを目標にするローグライトだが、その**スコアがプレイヤーに提示されていない**。`meta.best_depth` は保存も更新もされている（`game.ts` の `run_end()`）ものの、画面に出るのは死亡画面の「推奨深度: NF+」という間接的な形だけで、記録そのものを読む場所がない。

この設計は 2 つを足す。

1. 死亡画面のリザルトに **最高深度を常時表示する**
2. 記録を更新したランでは **ニューレコード演出を出す**

## スコープ

**死亡画面（`death-screen.ts`）のみを変更する。** プレイ中の HUD には深度を出さない。潜行中の常時表示は情報量を増やすが、中核の問い（ゲージが尽きる前に喫煙所を見つけられるか）に対して読む必要のない値であり、フロア到達時のターミナル通知（`深度 N に到達`）で足りている。

## データの受け渡し

`run_result_t` に `best_depth_before`（更新前のベスト深度）を 1 つ足す。

`run_end()` は `meta.best_depth` を更新した**後**に `death_screen_show()` を呼ぶため、画面側は原理的に「このランで更新されたか」を判定できない。更新前の値を控えて結果に載せるのが最小の変更で、「21F ← 15F」という対比表示にもそのまま使える。

更新後のベストは `run_result_t` には載せない。`meta.best_depth` から引く（死亡画面は既に推奨深度の算出で同じ値を読んでいる。ヤニ残高と同様、`meta` は表示中も読み続けてよい — 変わるのは購入によるヤニだけで、ベスト深度は表示中に動かない）。

## 発動条件

```ts
// death-screen-model.ts
export function is_new_record(depth: number, best_before: number): boolean {
  return best_before > 0 && depth > best_before
}
```

判定を `death-screen-model.ts`（DOM を触らない純関数のみ、Node/Vitest でモックなしに評価できる）に置くのは、`death_message()` / `condition_texts()` と同じ理由による。

**旧ベストが 0（＝未プレイ）のときは出さない。** 初回のランで 1F に届いただけの記録を「更新」として大げさに祝うと、演出そのものの意味が薄れる。2 回目以降のランで初めて出る。

同値（`depth === best_before`）は更新ではない。序盤は記録が連続して更新されるが、深くなるほど自然にレアになるため、深度のしきい値は設けない。しきい値を足すと説明のつかない定数が 1 つ増える。

## 表示

「今回の記録」パネルの `到達深度` の直下に `最高深度` 行を追加する。記録更新の有無に関わらず常時表示する（スコアを読めるようにすることが第一の目的であり、更新できなかったランでこそ「あと何階か」が要る）。

行のアイコンは到達深度と同じ `stat_depth_url` を流用する。同じ「深度」という量を指すので別のアイコンを起こす理由がない。

更新時はその行を金色（`#ffd24a`）に強調し、行末に `NEW` の小バッジを付け、値を `21F ← 15F` の対比表示にする。更新されなかったランでは強調もバッジもなく `21F` のみを出す。

演出のバナーは `NEW RECORD` を大きく、その下に `自己ベスト更新！ 深度 21F` を添える。世界観（闇サイトの端末）よりゲームとしての手応えを優先した文言で、死因メッセージや強化行の口調とは意図的に別の層に置く。

## 演出

`death-screen.css` の keyframes 連鎖で組む。

1. `0〜0.35s` — スライドイン ＋ スケール 1.4→1.0（`cubic-bezier` のオーバーシュート）
2. `0.35〜0.7s` — グリッチ。水平ずれ 3 回と、シアン／マゼンタの色収差（`text-shadow`）
3. `0.7s〜` — `#ffaa2b`（`.ds-title` と同色）のネオングロー呼吸を `infinite`、斜めのハイライトスイープを重ねる

効果音は既存の `audio_sfx_pickup` を 1 回鳴らす。専用の instrument を `sound-effects.ts` に足さないのは、1 箇所でしか鳴らさない音のために sonantx のパラメータ表を 1 つ増やす価値がないため。

## バナーを `render()` の外に置く理由

`render()` はキー入力と強化購入のたびに `root.innerHTML` を丸ごと組み直す。バナーをその HTML に含めると、**矢印キーを押すたびにスライドインとグリッチが再生し直される**。

そのためバナーは `#ds` の兄弟として `document.body` 直下に作る `position: fixed` 要素にする。`render()` の再構築の対象外になり、アニメーションは表示開始の 1 度だけ走る。

- `z-index` は `#ds`（10）より上
- `pointer-events: none`。下にある強化 UI のクリックを妨げない
- `death_screen_show()` が表示可否を決め、`descend()` が隠す
- 初回起動モード（`result === null`）では出さない

## 採用しなかった案

**到達深度をリザルトの主役に格上げする案。** 見出し直下に巨大な深度数字を置き、その数字自体を演出の対象にする。派手さは最大だが `.ds-left` の構成を作り直すことになり、記録パネル・状態パネル・イラストの縦の取り合いが変わる。得られるものが演出の派手さだけなのに対して、変更範囲が既存レイアウト全体に及ぶ。

**リザルトの前に全画面の割り込み演出を挟む案。** 最も派手だが、リザルト到達が毎回遅れ、スキップ操作の考慮が要る。「リザルトと闇サイトは 1 画面」という既存の設計方針（docs/meta-progression.md）とも噛み合わない。

## テスト

`death-screen-model.test.ts` に `is_new_record` の真理値表を足す。旧ベスト 0（未プレイ）・同値・超過・下回るの 4 通り。

実装完了後、`docs/meta-progression.md` の「死亡画面（リザルト＋闇サイト）とスコア」節に、最高深度の常時表示・演出・発動条件（旧ベスト 0 では出さない理由）を反映し、本ファイルを削除する。
