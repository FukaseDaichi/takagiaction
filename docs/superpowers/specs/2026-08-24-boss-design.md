# ボス戦（灰皿撤去ユニット）設計

深度が 5 の倍数のフロアを、部屋と通路の代わりに 1 つの闘技場にし、灰皿に居座るボスを倒して初めて一服できるようにする。撃破の報酬は、恒久強化 6 本のうち好きな 1 本を 1 段上げる権利と、押収品コンテナ 1 個（100%）。

## なぜ入れるか

`docs/gameplay.md`「中核ループ」は、要素を足すかどうかを **一問の緊張に効くか** で決めると規定している。ボス階はその一問を消すのではなく、**同じ問いを別の形に置き換える** ことで応える。

| | 通常フロア | ボスフロア |
| --- | --- | --- |
| 問い | ゲージが尽きる前に喫煙所を**見つけられるか** | ゲージが尽きる前に喫煙所を**空けられるか** |
| 主な消費 | 歩く距離 | 戦闘時間 |
| 答えの所在 | 間取りの中（探索） | 目の前（実行） |

喫煙所は最初から中央に見えている。それでも一服できないのは、灰皿の上にボスが座っているからで、**ゲージの残りと撃破にかかる時間の勝負** になる。5 階に 1 度この形を挟むことで、探索の緊張が「読み」だけに単調化するのを防ぐ。

## 世界観

ボスは **灰皿撤去ユニット**。5 階ごとに降りてきて、残存する喫煙所の灰皿を撤去して回る大型機である。

これは `docs/story.md` のダミー喫煙所（「灰皿だけ撤去された跡地」）に由来を与える。**通常フロアで踏む跡地は、こいつが既に仕事を終えた場所** という筋が通り、ダミーとボスが 1 つの設定で説明される。新しい設定を足しているのではなく、既にあった穴を埋めている。

トーンは `docs/story.md`「全体のトーン」に従う。高木は世界の危機に興味がないので、ボスに対する反応も「灰皿の上に座るな」の域を出ない。

## アリーナ

### 生成の分岐

`generate_level(depth, seed)` は `depth % 5 === 0` で `build_arena()` へ分岐する。返す型は `level_layout_t` のままで、次の 2 フィールドを足す。

- `boss: tile_pos_t | null` — ボスの位置。通常フロアは `null`
- `boss_spin: number` — 砲塔の回転方向（`1` / `-1`）

`load_level()` は `layout.boss` の有無だけを見る。**生成器は `renderer` / `dom` / `audio` を import しない** という `docs/gameplay.md`「生成器の契約」はそのまま守り、1000 シードの検証をモックなしで回せる形を崩さない。

### 形

**一辺 23 タイルの正方形 1 部屋。深度で広さを変えない。**

理由は 2 つある。1 つはレンダラの霧が `smoothstep(112, 16, 深度)` で切れること —— 中央から端まで 88px（11 タイル × 8）なら、**アリーナのどこに立っていてもボスが見える**。闘技場は相手が見えていなければ成立しない。もう 1 つは、回転掃射の間合いが弾速と自機の足だけで決まること。広さを深度で動かすと、同じボスの戦い方が深度ごとに別物になる。

したがって `level_bounds_side()`（深度 5 で 45）はボス階では使わない。範囲を深度で開く仕組みは、探索の空振りを浅い層で抑えるためのもので（`docs/gameplay.md`「フロアの広さは深度で開く」）、探索が無いこの階には効く相手がいない。

### 柱

**中心から半径 6 タイルのリング上に、45° ごとに 8 本。1 本は 2×2 タイル。**

格子状に並べないのは、中央のボスから見て全方向に等しく遮蔽がある必要があるため。格子だと隅が空いて安全地帯が偏り、周回が 360° 成立しなくなる。

2×2 は偶数辺なので、中心タイルに対する厳密な鏡像対称は取れない（正方向に +6、負方向に −7 と頭がずれる）。座標そのものは仕様ではなく、次の 3 つが不変条件である。

- どの柱も中央の灰皿タイルに接しない（詰めた自機が柱と灰皿に挟まれない）
- どの柱も外周の輪郭壁に接しない（柱の裏を通り抜けられる）
- 柱を置いたあとも全床タイルが連結している

実装は「23×23 を掘る → 柱のタイルを 0 に戻す → 既存の `build_walls()` を呼ぶ」の 3 手で済む。`build_walls()` は床に隣接する非床タイルを壁にするので、柱は自動的に壁として立つ。

### 配置

| 対象 | 位置 |
| --- | --- |
| 喫煙所（本物） | 中央 |
| ボス | 中央（喫煙所と同じタイル） |
| 開始地点 | 4 隅のいずれか（シードで選ぶ）。外周の輪郭壁から 2 タイル内側 |
| 非常口 | 開始地点の**対角**の隅 |
| ヘルスパック 2〜4 | 床から抽選。開始地点から BFS 距離 8 以上（`spawn_min_distance` を流用） |

非常口を対角に置くのは、「ボスを突破して向こうへ抜ける」構図が間取りだけで読めるため。

**置かないもの** と、その理由。

| 対象 | 理由 |
| --- | --- |
| ダミー喫煙所 | 探索が無いので、明滅が 2 つあっても損しか生まない |
| 蜘蛛・セントリー | 1 体との戦いに集中させる。`enemy_count()` はこの階では呼ばない |
| 清掃ドローン | 逃げ場のない 1 部屋では、逃走する収入源がただの的になる |
| 床のヤニ | 1〜3 個では収支が動かず、闘技場に置く意味がない |

ダミーを置かないことで、`docs/gameplay.md`「ダミー喫煙所」の深度テーブル（`min(floor(深度/5), 3)`）は実効値が変わる。ダミーが出るのは深度 6〜9 で 1、11〜14 で 2、16 以降で 3 になり、**5 の倍数ちょうどでは 0**。式は変えず、docs 側に注記する。

フロア到達ボーナス（ヤニ = 深度）は通常フロアと同じく入る。HP がフロアごとに 5 から始まるのも同じ。

### ミニマップと嗅覚に分岐を足さない

中央の喫煙所は未訪問なので既存の規則どおりオレンジで明滅し（`docs/gameplay.md`「明滅は行き先を意味する」）、それが**そのままボスの位置**でもある。ボス専用の印は要らない。

嗅覚も同じ。目標リストが中央の 1 点だけになるので「最寄りの残り香」は自明になるが、`meta_sniff_active()` の判定も `sniff.ts` の BFS もそのまま正しく動く。**位置を教える能力が、位置が既知の階で無力化されるのは設計どおり**であり（`docs/meta-progression.md`「嗅覚は段ごとに機能が解放される」の「答えるのは『どこにあるか』」）、例外を書く理由がない。ボス階でも収入系（Lv5）はコンテナに効き続ける。

### 頂点コスト

床 497 タイル × 6 ＋ 壁 128 タイル × 24 で約 6000 頂点。上限 `max_level_verts = 60000` に十分収まる。

## ボス

### 見た目と当たり判定

スプライトはアトラス **45 番**。`tools/atlas.py` の `TILE_RANGE` を `range(33, 46)` に伸ばす（43・44 は `slash_tiles.py` がコードから作る帯なので、元画像を置かなければ黙って飛ばされる）。

描画は `push_sprite()` を使わず **`push_quad()` を直に呼ぶ**。`push_sprite()` は 6×6 の固定サイズで拡大できないため、`entity-slash.ts` と同じくプリミティブ側から呼ぶ（`docs/architecture.md` が認めている経路）。サイズは通常スプライトの 2 倍（12 ワールド単位）、灰皿ブロックの上（`y = 8`）に立たせるので全高 20 になる。

当たり判定は `entity_t` に **`w = 9`** を足し、`game.ts` の衝突ループのハードコードされた 9 を `e1.w` / `e2.w` に置き換える。

```
!(e1.x >= e2.x + e2.w || e1.x + e1.w <= e2.x ||
  e1.z >= e2.z + e2.w || e1.z + e1.w <= e2.z)
```

既定値が現行のハードコード値と同じ 9 なので、**既存エンティティの挙動は完全に不変**。ボスだけ `w = 14` にする。見た目だけ大きくして判定を 9 のまま残すと、輪郭に撃った弾がすり抜けて「当たらない」という体験になる。

### 掃射

中央固定。移動せず、被弾ノックバックも受けない（`_receive_damage()` で速度を触らない）。

砲口が n 本、等角に並んだまま全体が一定の角速度で回り、**角度が一定量進むごとに全砲口から 1 発ずつ**吐く。時間ではなく角度で発射を刻むのは、回転速度を将来変えても弾の空間密度が変わらないため。

**これが柱と噛み合う要である。回転しているので、柱の陰（安全地帯）も一緒に回る。** 陰に留まれば射線が通るので、自機はボスの周りを同じ向きに回り続けることになる。回りながら撃ち返す形は `docs/gameplay.md`「操作」の後退射撃そのもので、**膠着が構造的に発生しない**。柱を「立ち止まって隠れる場所」ではなく「回り続ける軌道の目印」にするのが、この設計の中心である。

| 値 | 数値 |
| --- | --- |
| 角速度 | 0.5 rad/s（1 周 12.6 秒） |
| 発射間隔 | 0.18 rad ごと（≒ 0.36 秒） |
| 弾速 | 56（セントリーの 64 より遅い） |
| 弾のダメージ | 1（セントリーと同じ） |
| 接触ダメージ | 1 ＋ ノックバック（蜘蛛と同じ形） |

回転の向きはシードで左右どちらかに決める（`layout.boss_spin`）。固定すると間取りの暗記と同じ現象が起き、`docs/gameplay.md`「シード方針」の意図に反する。

### 弾はライトを積まない

同時に飛ぶ弾は最大で 6 砲口 × (1.6 秒 ÷ 0.36 秒) ≒ 26 発になり、`renderer.ts` の `max_lights = 16` を確実に超える。超過分は黙って捨てられるので（`docs/enemies.md`「清掃ドローン」のヤニと同じ現象）、光る弾と光らない弾が混ざる。

代わりにフラグメントシェーダの full-bright 規則（`t.r>0.95 && t.g>0.25 && t.b==0.0`）を使い、**既存の敵の赤 `(255,66,0)`** —— 蜘蛛（タイル 27）とセントリー（タイル 32）の目に使われている、まさにその色 —— で描く。この規則を満たす texel はライトも霧も通さず、全弾が等しい明るさで見える。弾幕は全部見えることが要件なので、これは妥協ではなく正しい経路である。ライトを持つのはボス本体 1 つだけ。

弾のタイル **46 番**は絵ではなく単色の点なので、`tools/slash_tiles.py` と同じく **コードから生成する**（`tools/boss_tiles.py`）。生成側が原本になるため再生成できる。画像生成が必要なのはボス本体 1 枚だけである。

### 深度スケール

**砲口の本数だけで表す。** 見た目で強さが分かり、実装は定数 1 つで、無限深度でも上限で頭打ちになる。回転速度と弾速は動かさない —— 本数と二重にスケールすると難度が跳ねる。

```
boss_arms(depth) = min(1 + floor(depth / 5), 6)
boss_hp(depth)   = 40 + 4 * depth
```

| 深度 | 砲口 | 耐久 |
| --- | --- | --- |
| 5 | 2 | 60 発 |
| 10 | 3 | 80 発 |
| 15 | 4 | 100 発 |
| 20 | 5 | 120 発 |
| 25 以降 | 6（上限） | `40 + 4 × 深度` |

深度 5 の 60 発は、素の射撃間隔 0.1 秒なら当てっぱなしで 6 秒、回避しながらで 20〜40 秒。同深度のゲージ寿命は約 72 秒（減少 1.38/s、最大 100）で、フロアに入るときのゲージは満タンではない。**倒せるが、のんびりはできない**帯に収まる。深度が上がるほど耐久と減少速度の両方が伸びるので、恒久強化（火力・耐性）がここで効いてくる。

### 既存の攻撃を通す配線

**放置するとボスに弾が当たらない。** 自機のプラズマ（`entity-plasma.ts` の `_check`）も薙ぎ（`entity-player.ts` の `_swing`）も、対象を蜘蛛・セントリー・ドローンの 3 クラスで名指し列挙している。ボスは両方に明示的に足す。

**刃物は当たるが、一撃必殺は効かない。** 薙ぎのループでボスを対象に含めたうえで、`kills` の条件からは外す。刃物 Lv9 以上の「硬さを無視して一撃で落とす」（`docs/equipment.md`）がボスに効くと、この設計が丸ごと消える。通常の `blade_damage()` は通すので、刃物ビルドが締め出されることもない。

### 撃破

**残弾を全部消す。** 消さないと、勝った直後に流れ弾で一服が中断され（`docs/gameplay.md`「一服」）、勝利の実感が濁る。`_kill()` が `state.entities` を走査してボスの弾を落とす。

カメラシェイクは序列の最上位に置いて **8**。`docs/enemies.md`「3 体に共通する規約」の序列は 蜘蛛 1 < セントリー 3 < 銘品 4 < 自機の死 5 < 清掃ドローン 6 < **ボス撃破 8** になる。この 1 本の尺度は揺れの大きさ自体が「何が起きたか」の合図なので、序列表ごと更新する。

音は既存の `audio_sfx_explode` を時間差で重ねる。**新しい sonantx の音色は足さない**（装備システムと同じ方針）。BGM のボス専用曲はスコープに含めない。

## 報酬

### ポーズは `state.paused` に統合する

現行のポーズは `game.ts` の 1 行（`state.equipping ? 0 : dt`）とエンティティループの 1 か所だけで効いている。ここへ 2 つ目のフラグを足すと `equipping || leveling` が 3 か所に散るので、**`state.equipping` を `state.paused` に改名**し、開封ダイアログとボス報酬ダイアログの両方が立てる。判定は 1 か所のまま残る。

`docs/gameplay.md`「ポーズは装備の開封だけ」は「開封とボス報酬の 2 つ」に更新する。

### ダイアログ

撃破の直後に開く。中身は恒久強化 6 本（肺活量・ニコチン耐性・嗅覚・脚力・火力・予備の一本）で、各行に「現在値 → 次の段の値」を出す。

**行の定義は死亡画面と共有する。** 6 行の表（名前・色・フレーバー・効果ラベル・任意段での値）は既に `death-screen.ts` にあり、値を `meta.ts` の getter から引いて式を画面側に書き写さない規約もそこで守られている。これを `upgrade-rows.ts` に切り出し、死亡画面とボス報酬の両方が読む。**同じ強化が 2 つの画面で別の書式になる余地を作らない。**

**表示する「現在の段」は `meta.levels[id] ＋ このランで既に選んだ回数`。** 報酬は `run_end()` まで `meta` に書かないので、素朴に `meta.levels[id]` を出すと、深度 5 と 10 で同じトラックを選んだとき 2 回とも同じ「現在 → 次」が出る。上限判定も同じ実効段で行う。

操作は `↑↓` で選んで `Enter`。**`Esc` は無い** —— 「どれか必ず 1 段」なので辞退の経路を作らない。上限に達した行は選べず飛ばす。見出しに **次の潜行から有効** であることを明示する（効果はラン中には現れないため）。

実装は `boss-reward.ts` ＋ `boss-reward.css`。`equip-screen.ts` / `equip-screen.css` の形に倣う。

**6 本すべてが上限のときは、ダイアログを出さずコンテナをもう 1 個落とす。** ヤニを配るより筋が通る —— 強化が満杯のプレイヤーにとって、まだ意味が残っている報酬は装備の段だけだからである。

### 押収品コンテナ 100%

撃破位置に 1 個落とす。床に落ちる walk-over なので、報酬ダイアログを閉じたあと歩いて拾いに行くことになり、**2 枚のダイアログが連続しない**。

段は `gear_roll_tier(depth, ...)` を **2 回引いて高いほうを採る**（best-of-2）。段を底上げする専用テーブルを持たせると `docs/equipment.md`「段の抽選は深度で重み付けられる」が壊れる。best-of-2 なら重み付けの形はそのままで期待値だけ上がるので、深く潜るほど良い装備という関係が保たれる。

### 適用はヤニと同じ場所・同じ寿命

選んだ id を `state.boss_levels`（`meta_upgrade_id_t[]`）に積み、`run_end()` が `meta.yani += state.yani_run` を書いている**そのブロック**で `meta.levels` に足し、`meta_save()` を 1 度だけ呼ぶ。`meta.ts` には価格を取らない `meta_grant(id)` を足す（`meta_buy()` はヤニを引くので流用しない）。

この形を選ぶ理由:

- **書き込み点が 1 つで済む。** ラン中に `meta.levels` を直接書くと、耐性・脚力・火力・嗅覚は毎フレーム `meta.levels` を読んでいるため（`game.ts` / `entity-player.ts` / `minimap.ts`）、6 本中 4 本だけがその場で効くという不揃いな挙動になる
- **寿命がヤニと完全に一致する。** 途中でタブを閉じれば消えるのも、死んでも全額残るのも同じ
- 死亡画面は `run_end()` の後に開くので、**闇サイトの強化行には既に +1 が乗った状態**で見える

`state.boss_levels` の型は `import type` で受けるので、`state.ts` の「実行時 import を一切持たない」契約は破れない。`run_start()` で空配列に戻す。

HUD にはラン中の獲得段を出さない（`docs/gameplay.md`「HUD は安全なときに黙る」）。

`docs/story.md`「声の使い分け」に従い、事実はターミナル・感情は吹き出しに割る。同時に出さず、つぶやきは遅らせる。

| 場面 | ターミナル | 高木 |
| --- | --- | --- |
| ボス階に到達 | 深度と大型機の検知 | 灰皿の上の何かへの反応 |
| 撃破 | ユニットの応答途絶 | どけと言った、の類 |

セリフは `monologue.ts` のプールに各 2〜3 種を持ち、直前と同じ行は選ばれない（既存の規約）。

## テスト

Node（Vitest）でモックなしに評価できる層へ寄せる。

- **アリーナ生成**（`level-generator.test.ts`）— 1000 シードで連結性、柱が灰皿にも輪郭壁にも接しないこと、開始と非常口が対角の隅であること、ボス階に蜘蛛・セントリー・ドローン・ダミー・床のヤニが 0 であること、頂点コストが上限内であること
- **掃射のモデル**（`boss-model.ts` ＋ テスト）— 砲口の角度列、発射を刻む角度しきい値、`boss_arms()` / `boss_hp()` の深度スケールの単調性と上限。`slash-model.ts` と同じ流儀で、3D の見た目は自動確認できないため形の性質だけをモデル側で固定する
- **報酬の実効段**（純関数）— `meta.levels[id] ＋ このランで選んだ回数`、上限に達した行の除外、全本上限の判定
- **`meta_grant()`**（`meta.test.ts`）— 上限クランプ、ヤニを引かないこと

## 採らなかった案

- **喫煙所を置かず、撃破そのものを一服の代わりにする** — 実装は最も単純だが、一服の三幕演出と煙感知器の理屈（吸う → 感知される → 扉が開く）がこの階だけ消える
- **ボスが二段階で変身し、灰皿を引き抜いて動き出す** — ドラマは最大だが、「灰皿を持って逃げる」経路が詰みを作りかねない。`docs/gameplay.md` は喫煙所が消費されない理由として、まさにこの詰みを挙げている
- **据え置き砲台 ＋ 蜘蛛の召喚** — 既存部品の組み替えで済むが、柱の陰が動かないため膠着しやすく、柱を置いた意味が薄い
- **深度ごとに別のボス** — 無限深度なので「何体目以降は使い回し」の線引きが別途必要になり、アセットと実装が体数分増える
- **報酬をヤニの大金にする** — 既存の経路（死亡画面で買う）に合流するだけで、撃破の瞬間に固有の報酬が無くなる
- **報酬をそのランから効かせる** — 効果を読む 6 か所すべてを「meta の段 ＋ ランの段」で引き直す必要があり、`meta.ts` の getter が持つ「段を引数で受ける」という単純な形が崩れる
