# 死亡画面の再設計 — 人体強化ステーション

## 目的

死亡画面を「大量の情報が並んだステータス画面」から「**自分の身体を直接触って強化している装置**」へ作り替える。常時表示の情報量を現行の 30〜40% まで落とし、削った情報は消さずに「常時表示 → フォーカス表示 → 詳細表示」の 3 階層へ再配置する。

到達点は 3 つ。

1. 画面へ入って最初の 1 秒で「生き返った」「ここで身体を強化できる」「地下へ戻れる」が分かる
2. 3 秒以内に「記録も装備も、必要なら確認できる」が分かる
3. `Tab` を押した瞬間に「この人体模型を操作して自分を改造するのだ」と直感できる

## フィクションの筋

**人体模型は闇サイト [Y-EXCHANGE] 側のインターフェースである。** 背景に写っている自席のラップトップが接続先で、そのサイトが高木の身体を図として描き、訓練プログラム（肺活量・ニコチン耐性・脚力）と物資（火力・予備の一本・嗅覚）を売ってくる。

この筋を採るのは、`docs/meta-progression.md` が「自席の端末が闇サイトに繋がっている、という**一つの理屈**で全項目の購入を説明する」を明文の方針として持っているため。地下施設に物理的な強化装置を新設すると理屈が 2 本になり、背景画（自席・ラップトップ・張り紙）とも噛み合わなくなる。

## 情報階層

| 階層 | 内容 | 出るとき |
| --- | --- | --- |
| **Level 1** 常時 | 人体模型、6 部位のアイコンと強化段数の円弧、ヤニ残高、記録確認、装備確認、地下へ戻る、キーヒント、死亡メッセージ | 常に |
| **Level 2** フォーカス | 能力名、フレーバー、効果の「現在値 → 次の段の値」、`Lv. n / max` とピップ、所持ヤニと必要ヤニ | 強化モードで部位を選択中 |
| **Level 3** 決定 | 記録確認パネル、装備確認パネル | `Enter` で開いたとき |

**強化に Level 3 は設けない。** Level 2 で判断材料が揃っており、`Enter` は購入そのものに割り当てる。最も反復される操作に確認ステップを挟まない。

**Level 2 / Level 3 の内容を Level 1 へ持ち上げない。** これがこの再設計の中心的な制約であり、以下の設計はすべてこの制約から導かれる。

| `body-figure.ts` | 人体模型の SVG ジオメトリ — 6 部位のアンカー座標、アイコン座標、接続線の経路、器官パス | 新規（純データ・Node 評価可） |

| `death-screen.css` | スタイルとアニメーション | 全面書き換え |
| `gear-icons.ts` | 装備アイコン 30 枚の静的 import | 新規（`equip-screen.ts` から切り出して装備確認パネルと共有） |

## DOM 方式 — 永続 DOM + 状態機械

**`death_screen_show()` が DOM ツリーを 1 度だけ組み、以降はノードを作り直さない。** 状態が変わったら class の付け外しとテキストノードへの代入だけを行う。

現行の `render()` は `root.innerHTML` をキー入力のたびに丸ごと組み直しており、この方式では CSS アニメーションがノードごと破棄されて位相が 0 に戻る。リポジトリは既にこの問題を踏んでおり、NEW RECORD バナーだけを `#ds` の**兄弟**へ逃がすという回避策が入っている（`death-screen.css` のコメントに理由が残っている）。部位 6 個・パネル 2 枚・扉・詳細パネルに同じ回避を繰り返すことはできない。

副産物として、**`#ds-nr` を `#ds` の兄弟に置く理由が消える。** バナーは `#ds` の内側へ戻す。

### 却下した案

| 案 | 却下理由 |
| --- | --- |
| `innerHTML` 再構築を維持し、演出を兄弟レイヤーへ逃がす | 演出はフォーカス対象そのものの上で起きる。バナーの回避策は対象が 1 個だから成立していた |
| 小さな仮想 DOM / テンプレートライブラリの導入 | js13k 由来の依存の薄い構成に依存を足す。手書きの状態機械 1 本で要件を完全に満たせる |

## 状態機械

```ts
interface ds_state_t {
  mode: 'idle' | 'upgrade'
  focus: number        // idle: 0..2（記録確認/装備確認/地下へ戻る）, upgrade: 0..5（部位）
  panel: 'none' | 'record' | 'gear'
  busy: boolean        // 演出の再生中。入力を捨てる
}
```

遷移は `ds_reduce(state, key): ds_state_t` の純関数 1 本が持つ。`death-screen.ts` は返ってきた状態と直前の状態を比べて class を当てるだけ。

| キー | idle | upgrade | パネル表示中 |
| --- | --- | --- | --- |
| `Tab` | `mode = 'upgrade'`、`focus = 0` | `mode = 'idle'`、`focus = 2`（地下へ戻る） | 無視 |
| `↑` / `←` | 3 項目を逆順に巡回 | 6 部位を解剖順の逆に巡回 | 無視 |
| `↓` / `→` | 3 項目を巡回 | 6 部位を解剖順に巡回 | 無視 |
| `Enter` | 記録確認 → `panel='record'` / 装備確認 → `panel='gear'` / 地下へ戻る → 降下 | 選択部位を購入 | 無視 |
| `Esc` | 降下 | `mode = 'idle'` | `panel = 'none'` |

**`Esc` は「1 段戻る」に統一する。** パネルが開いていれば閉じ、強化モードなら収納し、どちらでもなければ降下する。現行の「`Esc` で即降下」は最後の段として残る。

`busy` が真のあいだは全キーを捨てる。強化演出の途中で次の入力が入ると、演出とパネルの差し替えが同時に走って読めなくなる。

**`Tab` は `preventDefault()` が必須。** 外すとブラウザ既定のフォーカス移動が走る（`docs/equipment.md`「持ち替え」と同じ理由）。この画面と潜行中とで `Tab` の意味が 2 つあるのは既存の規約どおり。

### 強調階層（`ds_layer`）

§15 の 3 階層を状態から導出する。枠線で囲う表現は使わず、明度・発光・拡大で示す。`ds_layer()` は `'active' | 'dim' | 'inactive'` を返し、CSS 側が同名の class で受ける。

| 戻り値 | 明度 | 適用対象 |
| --- | --- | --- |
| `active` | 100% ＋ 周囲 120% の発光 ＋ アイコン 1.15 倍 | フォーカス中の 1 個 |
| `dim` | 65% | 同じモードで操作対象になっている残り |
| `inactive` | 35% | いまのモードでは触れないもの（強化モード中の記録確認・装備確認など） |

## レイアウトと座標

### 背景

`hero.webp`（1037×1516）を `background-size: cover` / `background-position: center 16%` で全面に敷く。16:9 では画像の高さの 38.5% にあたる帯が見え、**左＝高木の顔と煙草、右上＝「ニコチンは自由。」の張り紙、右下＝闇サイト端末（Y-EXCHANGE）** という構図になる。

その上に 3 枚を重ねる。

1. 全体の暗幕（明度を約 28% へ）
2. 周辺減光（ヴィネット）
3. 人体模型の背後だけを落とす放射状の暗がり

3 が要るのは、背景で最も明るい 2 点（張り紙・端末画面）が模型と同じ右半分にあるため。結果として「暗い部屋で模型だけが照らされている」画になり、§13 の「背景も見せる」と模型の可読性が両立する。

`cover` は縦にしか溢れないため `background-position-x` は効かない（構図は水平方向に固定）。

### 人体模型の SVG

`body.webp` は 256×512・RGB・背景 `rgb(12,15,12)`。実測した線の bbox は x 48〜208 / y 14〜491。

- 下地は `<img>` を `mix-blend-mode: screen` で敷く。背景が near-black なので黒が自然に抜ける
- 既定は `filter: saturate(.12) brightness(.55)` で灰色。フォーカス時だけ本来の色が戻る（§16）
- その真上に `viewBox="-80 -10 416 532"` の inline SVG を重ねる。SVG の座標系は下地の 256×512 とそのまま一致する

| 部位 | 強化 | 色 | body アンカー | アイコン |
| --- | --- | --- | --- | --- |
| 脳 | ニコチン耐性 `tolerance` | `#a86df0` | (128, 40) | 右 (290, 30) |
| 鼻 | 嗅覚 `sniff` | `#3af08a` | (128, 58) | 左 (-34, 70) |
| 肺 | 肺活量 `lung` | `#3ac6f0` | (128, 135) | 右 (290, 140) |
| 手 | 火力 `power` | `#f0932a` | (56, 262) | 左 (-34, 240) |
| 腰 | 予備の一本 `spare` | `#f0c93a` | (160, 248) | 右 (290, 300) |
| 脚 | 脚力 `leg` | `#f0568c` | (128, 360) | 左 (-34, 370) |

解剖順（脳 → 鼻 → 肺 → 手 → 腰 → 脚）で巡回し、アイコンは左右 3 個ずつ千鳥に置く。この割り当ては接続線が互いに交差しないように選んだ。色は `upgrade-rows.ts` が既に持っている値をそのまま使う（新しい色語彙を増やさない）。

**収納位置は、アンカーとアイコン定位置を結ぶ線分の 30% 地点とする。** 初期状態ではアイコンが身体のすぐ脇に寄り、強化モードで外側の定位置へ飛び出す（§5-3）。2 つの位置を別々の座標として持たず、比率 1 つで導出する。

**重ね順は 接続線 → 下地 → 器官 → アイコン。** 接続線を下地より下に置くと、身体の明るい線（腕など）の上を通る箇所だけが下地の発光で覆われ、「線が腕の後ろを通っている」という奥行きとして読める。下地は screen 合成なので黒い領域では線がそのまま透ける。腰から右へ伸びる線が右前腕を横切るのは解剖上そうなるためで、この重ね順によって不自然にならない。

### アイコンが常時持つ情報

**アイコンの外周に `level / max` の円弧を 1 本描くだけにする。** 数字も項目名も出さない。

- MAX は円弧が閉じて完全なリングになり、中央に小さなチェックが乗る（§7。`MAX` ボタンは置かない）
- ヤニ不足の項目は円弧とアイコンがわずかに赤みを帯びる（§8。赤く巨大な警告は出さない）

## 7 つの状態

### ① 初期状態

**出るもの**: 死亡メッセージ（3 秒後に存在感 40% へ）、模型、6 アイコン（内側の収納位置・彩度 15%）、記録確認、装備確認、地下へ戻る（既定フォーカス）、ヤニ残高、キーヒント。

**出ないもの**: 詳細パネル、接続線、記録パネル、装備パネル、すべての細かい数値。

#### 死因は見出しが担う

現行の見出し `ds-title` は死因によらず常に「死亡したよ、高木。」で、**死因の区別は削除対象の赤い箱の中だけにある**（`death_message()` が「やられたよ、高木。／次はもっと慎重に。」と「ニコチン、限界です。／しっかり整えて、また潜れ。」を出し分けている）。箱を消すと、敵に殺されたのかゲージが尽きたのかが画面から消える。

そこで `death_message(cause)` を**見出し 1 行を返す関数**に変える。

| 死因 | 見出し |
| --- | --- |
| 敵（`cause === 0`） | 死亡したよ、高木。 |
| ニコチン切れ | ニコチン、限界です。 |

2 行目（「次はもっと慎重に。」「しっかり整えて、また潜れ。」）は §2 の指示どおり削除する。サブテキストは死因によらず「救護ドローンが君を回収して、自席へ戻した。」のまま。これで **1 か所に 1 度だけ**死を伝え、しかも死因の 1 ビットは失わない。

#### ストレージ利用不可の警告

`meta.persistent === false`（プライベートモード等）のときの「強化はこのセッション限りで消える」警告は、**ヤニ残高の直下に 1 行、小さく赤で**出す。強化の原資が消えるという警告なので、残高の隣が唯一の正しい置き場になる。現行の闇サイト見出し内の位置は、見出しごと無くなる。

**既定フォーカスは「地下へ戻る」。** §11 が「この画面における最終的なメインアクション」と定め、§19 が「最初の 1 秒で地下へ戻れると理解できること」を求めているため。`Esc` も同じ動作なので、反射的な `Enter` で降下しても操作の損失は増えない。

### ② 強化モード展開中

`Tab` で ① から入る。§14 の時間差で 0 → 0.40s。

| 時刻 | 出来事 |
| --- | --- |
| 0.00s | 画面がわずかに暗転（暗幕 28% → 38%）、模型の輪郭が発光 |
| 0.08s | 選択部位の器官が点灯 |
| 0.16s | 接続線が `stroke-dashoffset` でアンカーからアイコンへ描かれる |
| 0.24s | 6 アイコンが収納位置から外側の定位置へ飛び出す |
| 0.32s | Level 2 詳細パネルが展開 |
| 0.40s | パネル内の数値が表示 |

同時に記録確認 / 装備確認が非操作階層（35%）へ後退する。強化可能な部位（ヤニが足りていて MAX でない）のアイコンだけが呼吸するように淡く明滅する。

もう一度 `Tab` を押すと、**数値 → パネル → 接続線 → アイコン → 模型** の逆順で収納される（`--i` を逆に振る）。

### ③ 能力フォーカス中

矢印キーで部位を移す。旧パネルの収納（0.12s）が始まった 0.10s 後に新パネルが展開する。両者が完全に直列だと待ち時間が体感で長く、完全に並列だと 2 枚が同時に見える。

Level 2 詳細パネルの内容:

```
肺活量
吸い方の訓練
最大ゲージ  150 → 160
Lv. 5 / 10   ●●●●●○○○○○
所持 52      必要 190
```

効果の数値は `meta.ts` の getter（段数を引数で受ける）から `upgrade_rows[].value(level)` 経由で引く。**式を画面側に書き写さない**（既存規約を維持）。MAX の段では「→ 次の値」と「必要ヤニ」の行を出さず、`Lv. 10 / 10  MAX` を出す。

### ④ 強化実行中

`Enter` で購入。`busy = true` にして 0.9〜1.2s の演出を再生し、終わったら ③ へ戻る。

ヤニが足りないときは購入が成立せず、**音を鳴らさない。** ヤニ残高と「必要 190」が 1 回だけ赤く震える。既存の `audio_sfx_hurt` は被弾音なので流用しない。

### ⑤ 記録確認

`Enter`（idle で記録確認にフォーカス）で開く。

| 時刻 | 出来事 |
| --- | --- |
| 0.00s | 背景の暗幕が 28% → 45% |
| 0.10s | パネルが画面左端からスライドイン |
| 0.20s | 古い端末の走査線が上から下へ 1 往復 |
| 0.35s〜 | 各行の数値が 70ms 間隔で順に点灯 |

同時に模型が 30% へ後退し、アイコンと接続線は収納される。`Esc` でパネルが左へ戻る。

内容は 到達深度 / 最高深度 / 生存時間 / 撃破数 / 喫煙回数 / ダミー踏み。記録更新した行は既存どおり `21F ← 15F` の対比と `NEW` バッジを出す。

**初回起動モード（`result === null`）では最高深度の 1 行だけに縮め、ベスト深度が 0 なら記録確認の項目ごと出さない。**

### ⑥ 装備確認

`Enter`（idle で装備確認にフォーカス）で開く。単純な文字リストではなく、**模型の装備部位から線が伸びて装備カードが展開する**形にする（§10）。

| 系統 | 模型上のアンカー | カード |
| --- | --- | --- |
| 刃物 `blade` | 右手 (200, 262) | 右へ展開 |
| ソール `sole` | 右足 (155, 478) | 右下へ展開 |
| パッチ `patch` | 胸 (128, 150) | 右上へ展開 |

カードは装備アイコン（`gear-icons.ts`）、系統名、等級色の品名を持つ。閉じるとカードが模型側へ吸い込まれるように収納される。3 系統とも未所持のあいだは装備確認の項目ごと出さない（現行の「パネルを出さない」を踏襲）。

強化アイコンはこのあいだ収納される。

### ⑦ 地下へ戻る直前

`Enter`（地下へ戻るにフォーカス）または `Esc`（idle）で入る。

| 時刻 | 出来事 |
| --- | --- |
| 0.00s | 全 UI が模型へ吸い込まれるように収納（逆順の階梯） |
| 0.35s | 照明が落ちる（暗幕が 90% へ） |
| 0.50s | 画面中央から緑（`#3af08a` 系）の光の裂け目が縦に開き、左右へ広がる |
| 1.00s | `on_descend()` |

**背景に扉は写っていないため、`door.webp` を背景へ貼らない。** 合成感が出る。代わりに `door.webp` は「地下へ戻る」ボタン内の小さなグリフとして使い、**画面そのものが開く扉になる**ことで §11 の「地下への扉が開く」を担う。`door.webp` は緑の光が漏れる半開きの扉なので、裂け目の色と一致する。

「地下へ戻る」にフォーカスしている間は、ボタン内の扉グリフの光の筋がゆっくり明滅する。

## アニメーション設計

### 段階開示の実装

各要素に CSS カスタムプロパティ `--i`（0 始まりの順番）を持たせ、`animation-delay: calc(var(--i) * 80ms)` で階梯を作る。収納は `calc((var(--n) - var(--i)) * 80ms)`。

**順序は CSS 変数 1 個で表現し、JS から個別の `setTimeout` を撒かない。** 並びを変えたときに時間差が自動で追従し、演出の途中で状態が変わっても JS 側にタイマーが残らない。

イージングは 2 種類に固定する。展開 `cubic-bezier(.2,.8,.2,1)`、収納 `cubic-bezier(.6,0,.8,.2)`。バウンスと粒子のキラキラは使わない（§6「重い・暗い・機械的」）。

### 部位別の強化演出

| 部位 | 演出 | SE |
| --- | --- | --- |
| 肺活量 | 肺 2 枚が `scale 1→1.28`（0.35s）→ 気管へ光が流れる（`stroke-dashoffset` 0.4s）→ 数値ロール → 肺が戻る → 口元から煙 3 粒 | `exhale` |
| ニコチン耐性 | 脳が点灯 → 脳→脊椎→四肢の神経ラインへパルス（部位ごと 60ms ずらし）→ 数値ロール | `hit` |
| 嗅覚 | 外周 6 方向から煙の粒子が鼻へ吸い込まれる（0.55s）→ 軌跡が一瞬線として可視化 → 解放名が差し替わる | `terminal` |

### 背景とヤニ残高の連動

購入が成立した瞬間、**背景の闇サイト端末が明滅し、そこから右上のヤニ残高へ細い線が走って残高が減る。** §13 の「ヤニ購入 → 闇サイト端末」を、ヤニ残高の位置を §12 どおり右上に据えたまま表現する。

### `prefers-reduced-motion`

`reduce` では段階アニメーションをすべて 0 秒にし、最終状態へ即座に置く。`index.html` が `#wf` / `#sl` / `#bf` で既に採っている流儀に合わせ、**JS 側に分岐を持たない**。

## テスト方針と、その限界

このリポジトリには jsdom / happy-dom が入っておらず、`test-setup.ts` は逆に Node の `localStorage` を外して「持たないブラウザ」を再現している。既存の `death-screen.ts` にテストが 1 本も無いのはこのため。**依存を増やさず、テスト可能なものをモジュールへ最大限押し出す。**

| モジュール | テストする性質 |
| --- | --- |
| `death-screen-model.ts` | `ds_reduce` の網羅 — idle の 3 項目巡回、`Tab` の展開と収納、強化モードでの 6 部位の解剖順巡回、パネル表示中は矢印無効、**`Esc` の 1 段戻る優先順位（パネル → 強化モード → 降下）**、`busy` 中は全キーを捨てる |
| `death-screen-model.ts` | `ds_layer` — §15 の 3 階層をどの状態でどの要素に割り当てるか |
| `body-figure.ts` | 6 アンカーが `body.webp` の実測 bbox（x 48〜208 / y 14〜491）に収まる、`meta_upgrade_ids` と 1:1 で対応する、左右それぞれのアイコンが縦に重ならない |

**限界を明示する。** 「状態 → class → 見た目」の配線は Node のテストでは押さえられない。ここは Browser ペインでの検証（スクリーンショット、`getAnimations()` によるアニメーション付与の確認と任意時刻へのスクラブ、`classList` の実読み）を証拠として出す。DOM UI なのでペインで動作する（WebGL 側の rAF 停止問題の対象外）。

変異テストの候補には、実装ファイルの内部だけでなく **その機能を成立させている最も外側の 1 行**（`death-screen.ts` から `ds_reduce` を呼ぶ行、`preventDefault()` の行）まで含める。
