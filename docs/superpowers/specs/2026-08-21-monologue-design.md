# 高木のモノローグ吹き出し 設計書

## 目的

初心者に「次に何をすべきか」をルール説明ではなく高木の欲望として伝える。ゲーム中のメッセージを 2 つの声に分離する:

- **ターミナル（既存・左上）** = 施設・生体端末の声。事実と指示（深度到達、非常口ロック解除、リザルト）
- **吹き出し（新設・自機追従 DOM）** = 高木の内心。目的・感情・切迫感

「灰皿は撤去されました」「咳き込んだ」など高木側の体験に属する通知は吹き出しへ移管する。世界観のトーン（docs/story.md「本人だけは大真面目なSFコメディ」）に従い、世界の危機や陰謀をほのめかす文言は書かない。

## モジュール構成

### projection.ts（純粋・テスト対象）

renderer.ts のシェーダに定数として埋まっている view / projection 行列を JS で再現し、ワールド座標 → CSS ピクセル座標を返す純関数。実行時 import を持たない葉モジュール（sniff.ts / nicotine.ts と同じ流儀）。renderer.ts は変更しない。

シェーダの計算は `gl_Position = r * v * vec4(p + cam, 1)`、`cam = (camera.x, camera.y - 10, camera.z - 30)`。GLSL の mat4 は列優先なので、展開すると:

```
q = p + cam
view:  u = (q.x,  0.707*(q.y - q.z) - 22.627,  0.707*(q.y + q.z) - 22.627,  1)
proj:  clip = (0.977*u.x,  1.303*u.y,  -u.z - 2,  -u.z)
ndc  = clip.xy / clip.w
css_x = (ndc.x + 1) / 2 * clientWidth
css_y = (1 - ndc.y) / 2 * clientHeight
```

シグネチャ: `project(x, y, z, cam_x, cam_y, cam_z, view_w, view_h): {x, y} | null`。`clip.w <= 0`（カメラ背後）なら null。cam_x/y/z には renderer の `camera` の値をそのまま渡し、-10 / -30 のオフセットは関数内で加える（呼び出し側にシェーダの知識を漏らさない）。

### monologue.ts（DOM + 状態機械）

API は 4 つ:

- `monologue_say(pool: string[], ambient?: boolean, delay?: number)` — プールから直前と同じ行を避けてランダムに 1 つ選び表示予約する
- `monologue_update(px, py, pz)` — game_tick から毎フレーム呼ぶ。遅延消化・文字送り・表示寿命・位置追従のすべてを `state.time_elapsed` 駆動で進める
- `monologue_notify_stage(stage)` — game_tick から毎フレーム呼ぶ。ニコチン段階の遷移監視と周期つぶやきを内包する
- `monologue_reset()` — フロア遷移時に呼ぶ。表示中・予約中のセリフを消す

**setTimeout を使わない。** すべての時間進行を `state.time_elapsed` で駆動する。terminal.ts の表示チェーンは `terminal_cancel()` が丸ごと捨てる構造で、降下予約がそこに載っていて消えた既知バグ（レビュー Finding 1）がある。吹き出しはこの構造に最初から加担しない。副次効果として、スローモーション時（フレーム落ち時の time_elapsed クランプ）もゲームと同期する。

### dom.ts / index.html

`index.html` に吹き出し要素（id は既存の 1〜2 文字流儀に合わせる）と CSS を追加し、`dom.ts` から `bubble_el` としてエクスポートする。

## 優先度は 2 段だけ

- **イベント発話**（フロア到達・ダミー・一服完了・一服中断・全回収）: 表示中のものを常に上書きする
- **アンビエント発話**（段階遷移のつぶやき・周期つぶやき）: 何も表示されていないときだけ出る

キューは持たない。イベント同士が同フレームで競合しうるのは「一服完了が最後の 1 箇所だった」場合だけで、これは呼び出し側の分岐で解決する（下記）。

## トリガーとセリフプール

| トリガー | 場所 | 種別 | プール |
| --- | --- | --- | --- |
| フロア到達（2 秒遅延） | game.ts load_level | イベント | 「どこかに喫煙所があるはずだ……」「頼むぞ、この階にはあってくれよ……」「灰皿の匂いがする……気がする」 |
| ダミー開示 | entity-smoking-area `_take_dummy` | イベント | 「くそっ、灰皿が撤去されてやがる……」「跡地かよ……匂いだけ残しやがって……」 |
| 全喫煙所回収済みでダミー開示 | `_take_dummy`（分岐） | イベント | 「もうここには喫煙所はない……」「……この階はもう用済みだ」 |
| 一服完了 | `_complete` | イベント | 「……最高の一服だぜ」「うまい……生き返るぜ……」 |
| 一服中断 | `_advance` | イベント | 「げほっ……！」「ちっ、落ち着いて吸わせろ……！」 |
| そわそわ突入（60%） | monologue_notify_stage | アンビエント | 「そろそろ一服したいな……」「……口寂しくなってきた」 |
| 離脱症状突入（30%） | 同上 | アンビエント | 「たばこ……たばこ……」「吸わせろ……吸わせろ……」 |
| 限界突入（0%） | 同上 | アンビエント | 「もう……限界だ……」「た……ばこ……」 |

- フロア到達の 2 秒遅延は、ターミナルの深度ログと同時に出さないため。遅延はフレーム駆動（monologue_update が消化）
- 段階遷移は**悪化方向のみ**発話する。改善方向（一服による回復）は黙って内部段階だけ更新する。これによりラン開始（満タン）で余計な発話が出ない
- 離脱症状以降は、何も表示されていなければ 10 秒ごとに同プールから再つぶやきする

### 「もうここには喫煙所はない……」の発火条件

そのフロアの喫煙所エンティティ（本物 + ダミー）が全部 `_done`。この状態では本物で一服済みなので非常口が必ず開いており、文言と状況が矛盾しない。判定は `_take_dummy` 内で `state.entities` を `entity_smoking_area_t` でフィルタして行い、成立時は通常のダミー用プールの**代わりに**このプールを使う。

一服完了（`_complete`）が最後の 1 箇所だった場合はこの分岐を入れず「最高の一服だぜ」を出す。非常口への誘導はターミナルのロック解除通知が担うため。

## ターミナル側の文言変更

- `_take_dummy` の「灰皿は撤去されました」→ ターミナル通知を廃止（吹き出しへ移管）
- `_advance` の「咳き込んだ」→ 同上
- `_complete` の「深く吸い込む...___非常口のロックが解除された」→「煙を感知___非常口のロックが解除された」（システムの声に統一。「深く吸い込む」は高木側なので吹き出しが担う）

深度到達・非常口通過・リザルトのターミナル通知は現状維持。予備の一本と音声トグルの通知もスコープ外（現状維持）。

## 見た目とアニメーション

- 自機の頭上（自機中心 x+3, y=8, z）を毎フレーム投影し、`transform: translate()` で追従。吹き出しの基準点は下端中央（`translate(-50%, -100%)` 合成）
- 画面端では左右にクランプ（吹き出しが見切れない程度の余白）。投影が null のフレームは非表示
- 半透明黒地 + オレンジ文字（#e90 系、既存 HUD と同系統）+ 下向きの小さな尻尾（CSS 三角形）
- 文字送りは 1 文字 50ms 相当をフレーム時間で進める。全文表示後 3 秒残して CSS transition でフェードアウト
- 離脱症状以降（stage >= withdrawal）は震えクラスを付与し、CSS keyframes で文字を小刻みに揺らす（camera.shake の手の震えと呼応）

## エッジケース

- **ラン終了**: run_end で吹き出しを消す（リザルト画面に高木のつぶやきを残さない）
- **フロア遷移**: load_level の monologue_reset() で表示中・遅延予約中のセリフを消す。段階遷移の記憶は消さない（ニコチンはフロアを跨いで持ち越されるため。悪化方向のみ発話の規則により、次ランの満タン開始でも誤発話しない）
- **プール選択**: 直前に出した行のインデックスを避ける（プールが 1 行しかなければそのまま）

## テスト

- `projection.test.ts`: 既知のカメラ・自機位置に対する投影結果（自機がほぼ画面中央に来ること）、カメラ背後で null
- `monologue.test.ts`: プール選択が直前と重複しないこと、文字送り・遅延・寿命の時間計算。DOM に触れる部分はテストしない（hud.ts / terminal.ts と同じ扱い）。時間計算を純粋に保つため、状態機械のロジックは DOM 書き込みと分離した形で実装する

## スコープ外

ダミー全ハズレ時の中間演出（「まだどこかにあるはずだ」）、非常口への方向誘導、セリフの深度変化、予備の一本・音声トグル通知の移管。いずれも必要になればプールとトリガーを足すだけで拡張できる。
