# hero タイトルレイヤー設計

hero.png（ダークティール×オレンジのピクセルアート・キービジュアル）をイントロの背景として表示し、ゲーム開始でフェードアウトする DOM レイヤーを追加する。UI 再設計の第一弾（スコープはタイトル画面のみ）。

## 決定事項

- 既存のターミナルイントロ演出（タイトル→ノイズ→ストーリー→クリックで開始）は変更せず、その背景に hero.png を敷く
- WebGL レンダラーは触らない。DOM レイヤー方式で実装する（320×180 アトラス前提のレンダラーに大判テクスチャを載せる案は過剰として却下）
- リザルト画面では hero を再表示しない（スコープ外。必要になれば表示関数の呼び出し 1 行で足せる）

## 構成

`index.html` に全画面レイヤー `<div id="h">` を 1 枚追加する。

- 重なり順（下から）: canvas `#c` → hero `#h` → ターミナル `#a`（ミニマップ・ゲージはイントロ中非表示なので関与しない）
- `#h` は `position:fixed; inset:0`、`background: url(m/hero.png) center/cover`
- スクリム: `#h` の上（`::after` または多重 background）に左上→右下の `linear-gradient`（上端は黒 70% 程度）を重ね、左上に出る琥珀色のターミナル文字の可読性を確保する
- ケンバーンズ: CSS アニメーションで 30 秒かけて `scale(1 → 1.06)`。動きはこれ 1 つだけ

## ライフサイクル

- ページ表示と同時に hero 表示（`index.html` に静的に存在するため JS 不要）
- ゲーム開始クリック（`source/main.ts` の `document.onclick`）の直後にフェードアウト開始: opacity 1→0 を 1 秒、完了後 `display:none`（`terminal_hide()` と同じ手法）
- 表示/非表示の操作は `source/dom.ts` に `hero_el` を追加して行う

## アセットとビルド

- `m/hero.png`（約 1.9MB）は `index.html` の CSS から相対参照する。Vite が index.html 内の参照を解決し、4KB 超のため `dist/assets/` にハッシュ付きファイルとして出力される
- 読み込みタイミング: ページロード直後から取得が始まり、ターミナル演出（数十秒）の間に完了する想定。プリロード指定は追加しない

## 検証

ロジックは「表示→開始クリックで非表示」のみのため vitest への追加はしない。ブラウザプレビューで以下を目視確認する:

1. イントロ中に hero が全画面 cover で表示される
2. ターミナル文字がスクリムにより全行読める
3. ゲーム開始クリックで 1 秒フェードアウトし、ゲーム画面の操作を妨げない
4. ウィンドウリサイズ時も cover が維持される
5. `npm run build` で hero.png が dist に出力され、preview でも表示される
