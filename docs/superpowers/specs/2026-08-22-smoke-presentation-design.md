# 一服演出・煙感知の因果・死亡白フェード 設計

docs/story.md の世界観（一服の至福、「一服すると煙感知器が作動し、非常口が開く」、救護ドローンの回収）を、テキストではなく音と光でプレイヤーに体感させる演出の追加。メカニクス（ゲージ・非常口の開通条件・死亡フロー）は一切変えない。

## 背景と診断

- 一服はゲーム全体で唯一のご褒美の瞬間だが、現状の演出は「ゲージの数字が駆け上がる + 完了時のビープ + セリフ」だけ。着火の音も、吸っている間の煙も、吐き出す一息もない
- 「煙感知器が作動して非常口が開く」という世界の中核ルールが、テキスト通知 1 行（`煙を感知___非常口のロックが解除された`）でしか語られない
- 死亡シーケンス（3 秒、`death-sequence-model.ts`）は実装済みだが、終端が死亡画面へのカット切り替えで、「白い光に包まれて運ばれた」の完結がない

## スコープ

1. 一服の三幕演出（着火・吸引・吐き出し）
2. 煙感知の因果を音で時差配置
3. 死亡シーケンス終端の白フェード

スコープ外: 死亡シーケンスのスキップ入力、離脱症状の音響演出（心拍等）、オープニングの早送り。いずれも検討の上で今回は見送り。

## 1. 一服の三幕演出

`entity-smoking-area.ts` の一服を「着火 → 吸引 → 吐き出し」の 3 幕にする。

| 幕 | タイミング | 演出 |
| --- | --- | --- |
| 着火 | `_advance()` で進捗が 0 から動き出す最初のフレーム | 新 SFX `sound_lighter`（短いノイズの擦過音）+ 灰皿位置に約 0.3 秒の強い暖色ライトフラッシュ |
| 吸引 | 一服中、0.6 秒ごと | 自機の位置から煙 1 つが立ちのぼる（既存 `spawn_smoke`。タイル 38） |
| 吐き出し | `_complete()` | 新 SFX `sound_exhale`（長いリリースの柔らかいノイズ = 深い吐息）+ 煙 3 つを一度に放出 |

- 煙は死亡シーケンスの「魂の煙」と同じ見た目・同じ実装を流用する。喫煙所の煙 = 高木の煙という同一性が、追加説明なしで世界観を通す
- 着火フラッシュはエンティティ内のフレーム駆動タイマー（`state.time_elapsed` 積算）で持ち、`_render()` の `push_light()` に係数として乗せる
- 中断（被弾）演出は現状維持（`monologue_interrupt` のみ）。中断時にタイマー類はリセットする
- 新 SFX は `sound-effects.ts` に `SonantInstrument` を 2 つ追加し、`audio_init()` で既存 7 つと同じ形で生成する。パラメータは dev サーバーでの試聴で調整する（実装計画に調整工程を含める）

## 2. 煙感知の因果（音の時差配置）

**メカニクスは変えない。** `state.exit_open = 1` は現状どおり `_complete()` の瞬間に立てる（遅らせると完了直後の死亡や降下との相互作用が生まれ、演出のためにコアループへ摩擦を足すことになる）。変えるのは音と通知のタイミングだけ。

`_complete()` 後のタイムライン（エンティティ内のフレーム駆動タイマー。setTimeout は使わない — 吹き出しと同じ方針）:

| 時刻 | 演出 |
| --- | --- |
| t=0 | 吐息 + 煙 3 つ（§1）+ `monologue_complete()`（既存） |
| t≈0.8 秒 | 感知器の音（既存 `audio_sfx_beep` を流用。現在 t=0 で鳴らしているものを移動）+ ターミナル通知「煙を感知___非常口のロックが解除された」（現在 t=0 のものを移動） |
| t≈1.5 秒 | 新 SFX `sound_door`（低い駆動音 = 遠くで防災扉が開く） |

- 「吸う → 感知される → 扉が動く」の因果が耳で追える。非常口の緑ライト明滅（`entity-exit.ts`）は `exit_open` に連動して即時開始するが、扉の駆動音が 1.5 秒遅れて届くのは「遠くの扉の音」として矛盾しない
- タイマーの発火判定は `state.game_running` でガードする。完了直後に死んだ場合、通知・音は残りを鳴らさない（リザルト表示中の `terminal_show_notice()` はターミナルの表示チェーンを壊す — 既存コメントの理由がそのまま効く）
- ダミー（`_take_dummy`）にはこのタイムラインを適用しない（感知器が作動しないからこそダミー）

## 3. 死亡シーケンス終端の白フェード

既存の死亡シーケンス（`death-sequence-model.ts` の時間割）は変えない。終端 3.0 秒の「`run_end()` → 死亡画面」のカット切り替えを、白フェードでつなぐ。

- 白い全画面オーバーレイ div を 1 枚追加する（`index.html` + CSS）。死亡シーケンスの持ち上げ開始（1.8 秒）以降、終端（3.0 秒）に向けて不透明度を上げ、真っ白になったところで死亡画面が表示され、白が明けて（不透明度 0 へ戻して）闇サイトが見える
- フェードイン開始・完了の時刻は `death-sequence-model.ts` に定数と純関数（経過時間 → 不透明度）で置き、Vitest でモックなしにテストする（既存の `death_body_y` / `death_drone_y` と同じ扱い）。DOM への適用は `game.ts` の死亡シーケンス分岐が行う
- `prefers-reduced-motion` ではフェードを省略し、従来どおりカットで切り替える
- フェードの白は「降りてきた白い光に包まれた」の完結であり、既存の「機体は描かず光と上昇だけで表現する」設計を保つ
- `run_start()`（次のラン開始）でオーバーレイの不透明度を 0 に戻す。死亡画面表示中にオーバーレイが入力を遮らないよう `pointer-events: none` にする

## エラー処理・エッジケース

- 一服中断: 着火済みでも煙・タイマーをリセットする。吸い直しでは再度着火（ライター音）から始まる
- 完了直後の死亡: §2 のタイムラインは `game_running` ガードで停止。白フェードは死亡シーケンス側なので競合しない
- 音声ミュート時（`audio_toggle`）: 既存の `audio_gain` 一括制御に乗るため個別対応不要
- リザルト表示中も rAF ループは回り続ける（docs/gameplay.md）。喫煙所のタイマーは `game_running` ガードで進行を止めるため、次のランへ持ち越さない（フロア遷移で喫煙所エンティティ自体が破棄される）

## テスト

- §2 のタイムライン発火判定は、`death_beats()` と同じ「(before, after] 区間に入った時刻」方式の純関数として切り出し、フレームが粗くても取りこぼさないことをテストする（置き場所は実装計画で決める。`entity-smoking-area.ts` は renderer に依存するため、純関数部分を分離する）
- §3 の不透明度関数は `death-sequence-model.ts` に置き、境界（1.8 秒・3.0 秒・範囲外）をテストする
- SFX の音色そのものは自動テスト対象外。dev サーバーでの試聴で確認する
- 既存テスト（`npm test`）と型チェック（`npm run typecheck`）が通ること

## docs への反映（実装と同じコミット群で）

- docs/gameplay.md「一服」: 三幕演出のタイムラインと、exit_open を遅らせない理由、フレーム駆動タイマーの理由を追記
- docs/gameplay.md「死亡シーケンス」: 白フェードの時刻と `prefers-reduced-motion` の扱いを追記

## 検討して採用しなかった案

- **exit_open を扉の駆動音（1.5 秒）まで遅らせる**: 因果の見た目は良くなるが、完了直後の死亡・降下との相互作用が生まれ、演出のためにメカニクスへ摩擦を足すことになる
- **死亡シーケンスのスキップ入力**: 3 秒は作り込まれており死亡頻度も分単位のため、複雑さに見合わない
- **救護ドローンの機体スプライト追加**: 既存の「光と上昇だけで表現する」設計が意図的な選択のため、上書きしない
- **感知器用の新 SFX**: 既存ビープで役割が足りる。新楽器は着火・吐息・扉の 3 つに留める
