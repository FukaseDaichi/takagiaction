# ニコチン・ローグライト化 設計書

作成日: 2026-08-18

## 概要

TAKAGI ACTION を「CPU端末を再起動して回るシューティング」から、**ニコチン切れと戦いながら喫煙所を探して潜り続けるアクションRPG（ローグライト）**に作り替える。

一言でいうと、ゲーム全体が一つの問いに収束する — *ゲージが尽きる前に、次の喫煙所を見つけられるか*。

## コンセプト

| 軸 | 決定 |
| --- | --- |
| 中核ルール | ニコチンゲージ（時間経過で減少、切れると弱体化） |
| 舞台 | SFのまま。2718年、喫煙が非合法化された施設 |
| 成長 | ローグライト型の恒久強化（通貨を持ち帰ってアンロック） |
| ランの形 | 深度無限・スコアアタック（到達フロア深度がスコア） |

舞台を現行のSF設定のまま維持することで、スプライトアトラス `m/q2.png` の描き直しが不要になり、ターミナル風の演出とストーリーも文面の差し替えだけで流用できる。

## 1. コアループ

未知のフロアに降りる → ニコチンゲージが減り続ける中で喫煙所を探す → 一服してゲージ全快 → 非常口が開く → 次のフロアへ潜る。尽きるまで繰り返す。

### ニコチンゲージ

| 項目 | 値 |
| --- | --- |
| 最大値 | 100（恒久強化「肺活量」で最大150まで） |
| 減少速度 | 毎秒 `1.0 × (1 + (深度 - 1) × 0.06)`（「ニコチン耐性」で最大 −30%） |
| 実時間の目安 | 深度1で約100秒、深度11で約62秒、深度21で約45秒 |

深度は1起点で数える（最初のフロアが深度1）。内部の `depth` 変数もこれに合わせ、計算式では `depth - 1` を使う。

HPバーとは別に、画面下部にゲージを表示する。

### 段階効果

- **100〜61%（通常）** — 変化なし
- **60〜31%（そわそわ）** — 自機が持つ光（`entity-player.ts` の `push_light`）の強度を落として視界を狭める。ミニマップの描き込み半径も連動して縮む。焦りを情報量の減少で表現する
- **30〜1%（離脱症状）** — 移動速度 128→96（×0.75）、射撃間隔 ×1.8、弾の拡散2倍、`camera.shake` を微量に常時加算して手が震える

射撃間隔は `基礎0.1秒 × 火力係数（強化） × ニコチン係数（離脱症状で1.8、それ以外1.0）` の順に掛けて求める。
- **0%（限界）** — 2秒ごとにHPが1減る。即死ではなく、まだ間に合う猶予帯

### 一服

喫煙所に触れると自動的に開始する（既存のCPU接触判定をそのまま踏襲）。2.5秒間、移動も射撃もできない。**無敵にはしない。**

これがアクション部分の核心で、「敵を掃除してから吸うか、追われながら賭けるか」の判断が毎フロア発生する。被弾すると中断するが、**吸った時間に比例してゲージが回復する**（1.5秒吸えたら60%回復）。全損にしないことで、中断が事故ではなく判断のグラデーションになる。

完了時: ゲージ全快、HP +1（最大値まで）、ヤニ +1、非常口が開通。

### ダミー喫煙所

「灰皿撤去済み」の空の喫煙所を混ぜる。ミニマップ上は本物と区別がつかず、触れて初めて `灰皿は撤去されました` と表示され、5%しか回復しない。深度が上がるほど本物1に対してダミーが増える。「歩き回って探す」体験の密度を決める要素。

## 2. フロア生成

新規ファイル `source/level-generator.ts`。グリッドは現行のまま 64×64 の `level_data`、タイル値の意味（0=空 / 1〜7=床 / 8以上=壁）も、壁と床のバリエーション抽選ロジックも既存を流用する。変わるのは「タイルをどこから決めるか」だけ。

### 手順

1. 幅・高さ 5〜11 の矩形部屋を 8〜12 個、互いに1タイル以上空けて配置（重なったらリトライ、上限200回）
2. 部屋 `i` と `i+1` の中心を幅2の L 字通路で接続 — 一本鎖なので連結性が構築上保証される
3. さらにランダムな部屋対を1〜2本繋いでループを作る。袋小路だけだと引き返しが単調になるため
4. `部屋[0]` = 開始地点
5. 本物の喫煙所 = `部屋[k]`、`k = min(3 + floor(深度/3), 部屋数-1)`。深度が上がるほど遠くなる
6. ダミー喫煙所 = `k` 以外の部屋から `min(1 + floor(深度/4), 3)` 箇所
7. 非常口 = **喫煙所の部屋を除いて**開始部屋から最も遠い部屋。一服完了までは閉じた壁として描画し、開通時に床へ差し替える。除外しないと、深度が上がって `k` が最終部屋を指したとき喫煙所と非常口が同室になる
8. 敵は床タイルごとの確率配置、深度でスケール。開始部屋周辺64px以内のスポーン除外は既存ロジックを流用

### 深度から整数を得ること

手順 5 と 6 の計算では **`Math.floor()` を明示的に使う**。JavaScript の `/` は整数除算ではないため、`3 + 深度/3` は深度が 3 の倍数でないとき小数になる。深度 1 なら `3.333...` で、`部屋[3.333]` は `undefined` になり本物の喫煙所が配置できない — つまりランが最初のフロアで詰む。`1 + 深度/4` も同様にダミー数が意図しない値になる。

`min` を取る前に `floor` を適用する（`min(3 + Math.floor(深度/3), 部屋数-1)`）。順序を逆にすると `部屋数-1` 側が選ばれたときに小数が残る余地がある。

### 副次的な簡素化

PNG読み込みが消えるとレベル生成が同期処理になるため、`load_level(id, callback)` の callback チェーンと `load_image()` が丸ごと不要になる。

### ミニマップ

フォグ・オブ・ウォーの仕組みはそのまま。色の意味だけ差し替える。

| 表示 | 意味 |
| --- | --- |
| オレンジ | 喫煙所（本物・ダミーとも同色） |
| 緑 | 非常口（開通後のみ表示） |

本物とダミーを同色にすることで、見分けは足で確かめるしかなくなる。「嗅覚」3段目のみ判別可能になる。

## 3. 通貨と恒久強化

### 通貨「ヤニ」

禁煙が非合法化された世界では吸い殻そのものが価値を持つ、という理屈。入手は3経路。

| 経路 | 量 |
| --- | --- |
| 敵ドロップ | 撃破ごとに50%の確率で1 |
| 床への散在 | 1フロアあたり 1〜3 |
| フロア到達ボーナス | そのフロアの深度と同数 |

**死亡時は全額持ち帰り、ロストなし。** ランごとに通貨を失う設計は「損した」感覚を残すだけで、深度を伸ばす動機にはならない。

### 強化メニュー

`terminal.ts` のターミナル風テキスト演出をそのままメニューUIに転用する（「自席の端末」）。新しい描画系が不要で、世界観にも合う。

| 項目 | 効果 | 段階 |
| --- | --- | --- |
| 肺活量 | 最大ゲージ +10 / 段 | 5（→150） |
| ニコチン耐性 | 減少速度 −6% / 段 | 5（→−30%） |
| 嗅覚 | 1段: ミニマップに喫煙所の方向矢印 / 2段: 距離表示 / 3段: ダミー判別 | 3 |
| 火力 | 射撃間隔 −12% / 段 | 3 |
| 予備の一本 | `E` キーでその場でゲージ50%回復。1段につきラン中の使用回数 +1 | 3（最大3回） |

コストは段階ごとに倍々（20 / 40 / 80 / 160 / 320）。嗅覚3段目のダミー判別は強力だが、終盤で世界が読みやすくなるのは恒久強化として正しい報酬なので、コストを高くして残す。

### スコアと保存

スコアは**到達フロア深度のみ**。複合スコアは分かりにくく、深度は「どこまで潜れたか」を一目で伝える。リザルト画面には深度・撃破数・獲得ヤニを表示し、ベスト深度だけ保存する。

保存は localStorage に1オブジェクト（ヤニ残高・各強化レベル・ベスト深度）。新規ファイル `source/meta.ts` に強化テーブルと保存・読み込みを置く。

## 4. 既存コードの削除・置換範囲

「後方互換性は維持しない」方針どおり、置き換えるものは残さず消す。

### 削除

- `source/entity-cpu.ts` — CPU再起動の概念ごと削除
- `m/l1.png` `l2.png` `l3.png` — 手続き生成に置換
- `load_image()`、`load_level()` 内のPNG色キー解析ループ（`game.ts`）
- `cpus_total` / `cpus_rebooted`（`state.ts`）
- `next_level()` の `current_level == 3` 終端判定（`game.ts`）— 無限深度に
- `reload_level()` と `entity_player_t._kill()` の「3秒後に同じフロア頭からやり直し」（`entity-player.ts`）— 死＝ラン終了に
- `terminal_run_outro()` のエンディング — リザルト＋強化メニューに置換

### 新規

- `source/level-generator.ts`
- `source/meta.ts`
- `source/entity-smoking-area.ts`

いずれも ESM モジュールとして書き、`export` した関数・クラスを利用側が `import` する。`index.html` に script タグを足す形（グローバル汚染）には戻さない — [TypeScript + Vite 移行](../../architecture.md)がその経路を削除しており、ESM エントリからは import されないモジュールは読み込まれもしない。

### 改修

| ファイル | 内容 |
| --- | --- |
| `game.ts` | `current_level`→`depth`、ニコチン状態の追加、`game_tick` にゲージ減少と描画 |
| `entity-player.ts` | 速度と射撃間隔をニコチン段階＋火力強化から算出 |
| `minimap.ts` | 色の意味の差し替え。`entity_cpu_t` の import（2 行目）と `minimap_draw()` 内の `instanceof entity_cpu_t` 判定（CPU 端末の見た目分岐）も `entity-cpu.ts` の削除に合わせて削除 |
| `terminal.ts` | ストーリー文面の書き換えとメニューUI |
| `index.html` | 変更不要（エントリは `source/main.ts` 1 本で、依存は import が表す） |

### 手を入れないもの

`renderer.ts`、`entity.ts`、各敵エンティティ、音声系一式、`random.ts`、`m/q2.png`。

敵のクラス名（`entity_spider_t` 等）もそのまま — 挙動もスプライトも変わらないため、リネームは混乱を増やすだけ。呼称の日本語化はUIテキスト側だけで行う。

### 含めないもの（YAGNI）

装備システム、ボス戦、難易度選択、セーブスロット、実績。

## 5. 破綻ポイントと対処

| 事象 | 対処 |
| --- | --- |
| 部屋が規定数置けない（200回試行で失敗） | 置けた分で続行。ただし最低3部屋を保証し、下回ったらシードを変えて再生成 |
| 非常口が開始部屋と同一になる | 最低3部屋保証で回避される |
| localStorage が使えない（プライベートモード等） | try/catch でメモリ内フォールバック。恒久強化がセッション限りになる旨をメニューに表示 |

## 6. 検証

数値ロジックは Vitest でテストする。フロア生成（部屋の非重なり、全部屋の連結性、喫煙所と非常口が別室であること、深度ごとのダミー数）、ゲージ減少速度、射撃間隔の三段乗算はいずれも純粋関数に切り出せるので、ここは手動確認に頼らない。`random.ts` がシード付きなので生成結果は再現可能。

生成器は特に念入りに検査する。1000シードぶん生成し、開始部屋から喫煙所・ダミー・非常口すべてに BFS で到達できることを確認する。連結性のバグは手動プレイでは滅多に踏まないため、ここは自動テストでしか現実的に検出できない。

体感（見え方、難易度、テンポ）は `npm run dev` での手動確認。
