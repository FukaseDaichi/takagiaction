# 清掃ドローンの速度再設計

## 問題

清掃ドローンが簡単に倒せてしまう。原因は逃走速度ではなく**巡回の鈍さ**にある。

`drone_wander_accel = 80`（摩擦 5 なので終端速度 16px/s）は自機の素の足 25.6px/s の 6 割で、巡回先は自分の周囲 ±32 単位（4 タイル）からしか選ばず、しかも 0.7 秒ごとに引き直す。1 脚あたりの移動距離は 16 × 0.7 = **11 単位**しかない。カメラの画角が自機周囲およそ ±50 単位、フロアが 512×512 単位（64×64 タイル × 8）であることを踏まえると、ドローンは画面の一角でその場足踏みしているに等しい。

結果として、プレイヤーは逃走が始まる前に無抵抗の的へ歩み寄れる。逃走の終端速度 30px/s が「素の足では追いつけない」ように設計されていても、**逃走に入る前に殴れるなら意味を持たない。**

## 決定

| 定数 | 現行 | 新 | 終端速度 | 1 脚の移動距離 |
| --- | --- | --- | --- | --- |
| `drone_flee_accel` | 150 | **300** | 30 → **60px/s** | — |
| `drone_wander_accel` | 80 | **150** | 16 → **30px/s** | — |
| 巡回先の半径 | ±32 | **±96** | 4 → 12 タイル | — |
| 巡回先の保持時間 | 0.7 秒 | **2.0 秒** | — | 11 → **60 単位** |

変更は `entity-drone.ts` の 4 箇所に閉じる。新しい状態・分岐・オプションは追加しない。

## 逃走は「逃げ切る手段」ではなく「距離をリセットする瞬発力」である

これがこの再設計の中心にある転換で、以下の帰結はすべてここから出る。

逃走の 60px/s は自機の**絶対上限 45px/s**（脚力 Lv10 の 200 ＋ ソール Lv10 の +25 = 225）を上回るので、どんなビルドでも走って追い越せない。しかし逃走は 64px 離れれば解除される（`drone_release`、ヒステリシス）。解除後のドローンは巡回速度 30px/s へ落ちる。

したがって**追跡が成立するかどうかを決めるのは巡回速度であって、逃走速度ではない。** 脚力 Lv4 以上のプレイヤーの体験は「詰める → 60px/s で振り切られる → また詰める」の反復になり、これはフロアの端へドローンを追い込む行為そのものである。**既存の撃破ルートである「壁際への追い込み」は弱まるのではなく、追跡の主たる形になる。**

## 解禁しきい値は数値を動かさず、意味だけが変わる

自機速度は `128 × (1 + 0.05625 × 脚力Lv) + 2.5 × ソールLv`。巡回速度を 150 に置くと、しきい値の比較が現行とまったく同じ形で残る。

| | 加速度 | vs 巡回 150 |
| --- | --- | --- |
| 素の足 | 128 | 追いつけない |
| 脚力 Lv3 | 149.6 | 追いつけない |
| **脚力 Lv4** | **156.8** | **追いつく** |
| **ソール Lv9** | **150.5** | **追いつく**（拾い物としてのもう 1 本のルート） |

docs/meta-progression.md「強化テーブル」の「Lv4（156.8）が 150 を追い越す」と docs/equipment.md「ソールの上限に意味がある」の「128 + 25 = 153 が 150 をちょうど超える」は、**文字どおり正しいまま残る**。150 という数が逃走速度から巡回速度へ移っただけである。

変わるのは勝ち取るものの中身だけ:

- 旧: 逃げるドローンを走って追い越して倒す
- 新: 巡回するドローンに追いついて射程に入れる

**買う道（脚力）と潜って拾う道（ソール）が同じご褒美へ別経路で届く**という docs/equipment.md の構造は保存される。

### 離脱症状はドローン狩りの側でも効く

離脱症状帯の基礎速度 96 に脚力 Lv10 の係数 1.5625 を掛けると **150 ちょうど**で、新しい巡回速度と同速になる。**離脱症状中は脚力を全振りしても巡回するドローンに追いつけず、ソールを拾って初めて届く。** docs/meta-progression.md の「離脱ペナルティはどの段でも消えない」が、ドローン狩りという具体的な場面で観測できる形になる。これは偶然の一致だが、方向が正しいので採用する。

## 撃破手段の収支

自機のプラズマは速度 96px/s の固定値（`entity-plasma.ts`）なので、まっすぐ逃げるドローンへの接近速度は `96 − ドローンの終端速度`。

| 状態 | ドローン | 接近速度 |
| --- | --- | --- |
| 現行の逃走 | 30px/s | 66px/s |
| 新・巡回 | 30px/s | 66px/s |
| 新・逃走 | 60px/s | **36px/s** |

逃走中に当て続ける難度は 1.8 倍になるが、**「撃てば確実に落ちる」は失われない。** HP 10 は据え置く。刃物 Lv5 以上の一撃必殺（docs/equipment.md）は距離を詰められることが前提なので、「追いついて射程に入れる」という新しい解禁の意味と噛み合う。

**接近速度が負にならないことがこの設計の下限である。** 逃走の終端速度が 96px/s を超えると弾が永久に追いつかず、逃走に入った瞬間から撃破不能になって収入源（ヤニ 深度 × 30）が実質消える。60px/s はこの壁に対して十分な余裕を持つ。

## 速度序列

摩擦はどれも 5 なので終端速度は加速度の 1/5。docs/enemies.md「足の速さは自機を挟んで分かれる」の 1 本の尺度に、ドローンが 2 つの値で載る。

| | 加速度 | 終端速度 |
| --- | --- | --- |
| **ドローン（逃走）** | **300** | **60px/s** |
| 自機の絶対上限（脚力 Lv10 ＋ ソール Lv10） | 225 | 45px/s |
| 自機（脚力 Lv10） | 200 | 40px/s |
| 蜘蛛 | 160 | 32px/s |
| **ドローン（巡回）** | **150** | **30px/s** |
| 自機の通常歩行 | 128 | 25.6px/s |
| 自機（離脱症状） | 96 | 19.2px/s |
| セントリー | 48 | 9.6px/s |

**ドローンは巡回中ですら蜘蛛に次ぐ速さで、逃走ではフロア最速になる。** 非武装の相手が最も速いという配置は、docs/enemies.md「清掃ドローンは逆に足を伸ばさせる」という 3 体の役割分担を強める。

## 採用しなかった案

| 案 | 却下の理由 |
| --- | --- |
| 逃走 150 据え置き、巡回だけ速くする | 解禁しきい値は無傷で済むが、「追いついた後は無抵抗」という現行の手応えが残る。逃走が距離をリセットしないと追い込みの反復が生まれない |
| 逃走の終端速度を 300px/s にする | 弾（96px/s）が永久に追いつかず、逃走に入った瞬間から撃破不能になる。収入源が実質消え、メタ進行の収入設計まで作り直しになる |
| 索敵距離 40 → 64 に広げる | 蜘蛛・セントリーと揃って規約は綺麗になるが、巡回速度を上げれば接近の困難さは足りる。同時に動かすと、どちらが効いたのか試遊で切り分けられない |
| 逃走中に壁を避ける経路を持たせる | 「壁際への追い込み」という docs/enemies.md が明記する撃破ルートを潰す。追跡の主たる形にする方針と正面から衝突する |
| ドローンの HP を上げる | ユーザーの要求は移動の話であり、耐久はドローンを「硬い的」にするだけで動きの手応えを変えない |

## テスト

`entity-drone.test.ts` に追加する。

1. **速度序列の固定** — 巡回の終端速度が自機の素の足（25.6px/s）を上回り、逃走が自機の絶対上限（45px/s）を上回る。加速度の生値ではなく終端速度で表明し、摩擦を変えた変異も殺す
2. **接近速度が正であること** — 逃走の終端速度がプラズマの 96px/s を下回る。上の「下限」を回帰から守る
3. **到達可能距離** — 実際に生成したフロアで巡回させ、N 秒後の移動距離を測る。壁に囲まれて足踏みするだけの実装を殺す。乱数を含むので閾値は 1 サンプルではなく「N シード中 M 以上」の集計統計にし、現行実装と最も生き残る変異体の実測値の間に置く
4. **巡回先の保持時間** — 0.7 秒経過では目的地を引き直さず、2.0 秒経過で引き直す。現行値 0.7 を殺す
5. **巡回先の半径** — 引き直した目的地が自機周囲 ±32 を超えて散る。半径の縮小変異を殺す

3 は「壁の中に入らない」ことではなく「壁を回避して進める」ことを見る。前者は後者を保証しない。
