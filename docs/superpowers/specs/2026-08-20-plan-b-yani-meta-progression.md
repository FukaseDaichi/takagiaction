# 計画B: 通貨「ヤニ」と恒久強化 設計書

作成日: 2026-08-20（2026-08-18 のニコチン・ローグライト化設計書から、未実装の計画B部分のみを抜き出して再編。計画Aの結論は docs/gameplay.md に蒸留済み。同日、ストーリー整合性と中核ループ保護の観点でレビューし改訂）

## 概要

ローグライト中核（計画A、実装済み）に、ラン間の恒久強化を足す。通貨「ヤニ」を持ち帰り、自席の端末（ターミナル風メニュー）でアンロックする。

## 通貨「ヤニ」

喫煙が非合法化された世界では、吸い殻そのものが闇で価値を持つ、という理屈。入手は3経路。

| 経路 | 量 |
| --- | --- |
| 敵ドロップ | 撃破ごとに50%の確率で1 |
| 床への散在 | 1フロアあたり 1〜3 |
| フロア到達ボーナス | そのフロアの深度と同数 |

**死亡時は全額持ち帰り、ロストなし。** ランごとに通貨を失う設計は「損した」感覚を残すだけで、深度を伸ばす動機にはならない。

## 強化メニュー（闇サイト）

`terminal.ts` のターミナル風テキスト演出をそのままメニューUIに転用する。新しい描画系が不要で、世界観にも合う。

世界観上の理屈: 自席の端末は愛煙家の闇サイトに繋がっており、吸い殻（禁制品）を送ると見返りが届く。「火力」「予備の一本」は物資、「肺活量」「ニコチン耐性」「嗅覚」は闇サイトの怪しい訓練プログラム。全項目をこの一つの理屈で説明する。メニューのフレーバーテキストは闇サイト風にするが、世界の危機や陰謀をほのめかす文言は足さない（docs/story.md のトーン指針に従う）。

| 項目 | 効果 | 段階 |
| --- | --- | --- |
| 肺活量 | 最大ゲージ +10 / 段 | 5（→150） |
| ニコチン耐性 | 減少速度 −6% / 段 | 5（→−30%） |
| 嗅覚 | 1段: ゲージ30%以下のとき、ミニマップに最寄りの「残り香」への方向矢印 / 2段: 発動閾値を60%以下に緩和 / 3段: 距離表示を追加 | 3 |
| 火力 | 射撃間隔 −12% / 段 | 3 |
| 予備の一本 | `E` キーでその場でゲージ50%回復。1段につきラン中の使用回数 +1 | 3（最大3回） |

コストは段階ごとに倍々で、5段項目は 20 / 40 / 80 / 160 / 320、3段項目はその先頭3つ（20 / 40 / 80）を使う。全解放の合計は 1660。

### 嗅覚が「低ゲージ時のみ」である理由

ゲームの中核の問いは「ゲージが尽きる前に喫煙所を見つけられるか」（docs/gameplay.md）。恒久的な方向ナビはこの問いを恒久的に無効化するため、嗅覚は**追い詰められたときだけ働く救済**に限定する。切羽詰まるほど煙草の臭いに鼻が利く、というフレーバーで、離脱症状の演出とも噛み合う。

矢印は本物の喫煙所とダミーを**区別しない**。最寄り（開始部屋中心からではなく自機からの BFS タイル距離）の喫煙所またはダミーを指す。跡地にも残り香はある、という理屈で、嗅覚を積んでもダミー喫煙所の「歩いた時間の損」という緊張は残る。旧案にあった3段目のダミー判別は、ダミーという設計要素そのものを消すため廃止した。

### 予備の一本と煙感知器

この世界のルールは「一服すると煙感知器が作動し、非常口が開く」（docs/story.md）。予備の一本はこのルールと矛盾しないよう、**こっそり浅く吸うので感知器には届かない**、という理屈にする。だから回復も 50% 止まりで、非常口も開かない。警報リスクを付ける案（吸うと敵が寄ってくる）も検討したが、緊急回復ボタンとしての役割が主目的であり、実装の単純さを優先して見送った。

## スコアと保存

スコアは**到達フロア深度のみ**。複合スコアは分かりにくく、深度は「どこまで潜れたか」を一目で伝える。リザルト画面には深度・撃破数・獲得ヤニを表示し、ベスト深度だけ保存する。

保存は localStorage に1オブジェクト（ヤニ残高・各強化レベル・ベスト深度）。新規ファイル `source/meta.ts` に強化テーブルと保存・読み込みを置く。localStorage が使えない環境（プライベートモード等）は try/catch でメモリ内フォールバックし、恒久強化がセッション限りになる旨をメニューに表示する。

## 数値の接続

射撃間隔は `基礎0.1秒 × 火力係数（強化） × ニコチン係数（離脱症状で1.8、それ以外1.0）` の順に掛ける。`nicotine.ts` の `shot_interval()` に火力係数の引数を足す形（テスト `nicotine.test.ts` にその旨のコメントあり）。減少速度は √ 式（`nicotine_drain_rate`）が採用済みで、全強化の実効倍率 2.143 との釣り合い点は深度 37。

嗅覚の発動閾値 30% / 60% は `nicotine_stage()` の段階境界（離脱症状 / そわそわ）と同じ値を使う。段階判定が比率ベースである以上、嗅覚も比率で判定する。

## 実装先の注意（設計レビューで確定した点）

- **敵ドロップ**は各敵エンティティの `_kill()` に手を入れる必要がある（計画Aの「敵エンティティには触れない」方針はここで解除）
- **床のヤニ**を拾うエンティティ（`entity_health_t` 相当）を新規に作る
- **`E` キー**は `input.ts` の `keys` に追加が必要。押しっぱなしで 1 のままなので、1回だけ発動させるにはエッジ検出が要る（`M` キーが `!ev.repeat` で特別扱いされているのと同じ問題）
- 強化レベル・ヤニ残高などラン間で持ち越す状態も、ラン状態と同じく `state.ts` ではなく `meta.ts` 側に置く（ラン状態と寿命が違うため）
- **嗅覚の矢印**が使う「自機からの BFS 距離」は、既存の「開始部屋中心からの BFS 距離」（配置用）とは別物。毎フレーム BFS を回すのは過剰なので、更新はフロア生成時＋一定間隔（例: 1 秒ごと）で足りる

## 含めないもの（YAGNI）

装備システム、ボス戦、難易度選択、セーブスロット、実績。予備の一本への警報ペナルティ、嗅覚のダミー判別。
