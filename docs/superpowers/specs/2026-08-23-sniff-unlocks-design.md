# 嗅覚の機能解放化（Max5）

嗅覚トラックを「10 段のしきい値スケーリング」から「5 段の機能解放」へ組み替える。

## 動機

現行の嗅覚は 10 段すべてが発動しきい値（`0.3 + (段-1) × (0.3/9)`）だけを動かす。1 段あたり 3.33pt で、33.3% や 46.7% といったニコチン段階の境界と一致しない値を 8 つ通過する。`docs/meta-progression.md` はこの帯を「いつ働き始めるかを早めるだけの息の長い贅沢枠であり、他トラックと競い合う購入にはならない」と自ら記録している。買っても何も起きた気がしない、という構造上の問題である。

段ごとに別の能力が解放される形にすると、5 段それぞれが 1 文で言える変化になる。

## 段の定義

| 段 | 解放 | 効果 |
| --- | --- | --- |
| 0 | — | 何も起きない |
| 1 | 方向 | ゲージ 30% 以下で、最寄りの残り香へ向かう光跡。角度はユークリッドで、壁を指すことがある |
| 2 | 早さ | しきい値が 60% 以下へ |
| 3 | 筋 | 光跡が経路方向（BFS の第一歩）になり、`残り香 Nm` の距離表示が出る |
| 4 | 抜け道 | 残り香が尽きたあと、開通済みの非常口も嗅ぐ |
| 5 | 金 | ヤニと清掃ドローンが、未探索タイルでもミニマップに点灯する。しきい値と無関係に常時 |

累積である。Lv3 を買っても Lv1〜2 の効果は消えない。

## しきい値は 30% / 60% の 2 値

Lv1 が 30%、Lv2 以降が 60%。連続値をやめる。

**どちらもニコチン段階の境界そのものである。** 30% は離脱症状の入口、60% はそわそわの入口（`nicotine.ts` の `nicotine_withdrawal_ratio` / `nicotine_edgy_ratio`）。段階境界に一致させると Lv1 は「離脱症状になったら鼻が利く」、Lv2 は「そわそわし始めたら鼻が利く」と 1 文で言える。10 段の刻みが持っていた中間値は、どの段階とも対応しないため説明できなかった。

上限を 60% に留める理由は従来どおり。恒久的な方向ナビは中核の問い（ゲージが尽きる前に喫煙所を見つけられるか）を恒久無効化する。

判定は比率（`state.nicotine / state.nicotine_max`）で受ける。段階の判定を `meta.ts` に持ち込まないため。この形により `meta.ts` は実行時 import を 1 つも持たない葉モジュールのままである。

## 生存系と収入系は別の感覚

| 系 | 対象 | 表現 | 発動条件 |
| --- | --- | --- | --- |
| 生存系 | 喫煙所の残り香、開通済みの非常口 | ミニマップの光跡（方向） | しきい値以下 |
| 収入系 | ヤニ、清掃ドローン | ミニマップの点（位置） | 常時 |

**収入系をしきい値で縛らない。** 追い詰められている最中にヤニの位置を教えられても拾いに行く余裕はなく、狩りの道具として使う場面が消える。中核の問いを守るには喫煙所への矢印だけが 60% 以下に縛られていれば足りるので、収入系を常時にしても問いには触れない。

**収入系を矢印ではなく点にする。** 矢印 1 本の取り合いが原理的に起きなくなる。「生存系＝方向、収入系＝位置」という感覚の分離自体が、なぜ表現が違うのかの説明になる。ヤニと清掃ドローンは現在ミニマップにまったく描かれていない（`minimap_draw()` が描くのは喫煙所と非常口だけ）ため、実装は `minimap_explored` のガードを通さない描画を足すだけである。

清掃ドローンを対象に含めるのは脚力とのシナジーのため。脚力 Lv4（速度 156.8）でドローンの逃走終端速度 150 を追い越して狩りが解禁されるが、獲物を見つける手段は素の探索しかなかった。

**Lv4 の優先順位は「残り香 > 非常口」だが、分岐は書かない。** 目標が空になるのは本物を吸い終えたときだけである（フロアには本物が必ず 1 つあるので、全部 `_done` ⟹ 一服済み ⟹ `exit_open`）。`exit_open` のとき非常口を目標リストへ足すだけで、残り香が残っている間は BFS 距離の比較で自動的に残り香が選ばれる。

Lv4 が埋めるのは「一服後に非常口を探して歩き回り、ゲージが再び 60% を割った」局面である。現行実装ではこのとき目標リストが空になり、嗅覚が完全に沈黙する。

## 価格は共通曲線を 1 段飛ばしでサンプルする

嗅覚の N 段目の価格は `meta_upgrade_cost((N-1) × 2)`。**15 / 55 / 135 / 255 / 415、合計 875。**

共通曲線をそのまま使うと合計 325（10 段トラックの 1/6）で、5 つの機能を解放するトラックが最安になる。曲線そのものを嗅覚だけ別式にすると `docs/meta-progression.md` が保証している「価格曲線が全トラック共通」という性質が失われる。1 段飛ばしのサンプリングなら式は 1 本のままで、10 段トラック 2025 に対して 43% に収まる。

全解放の合計は 10 段 × 4 本（肺活量・耐性・脚力・火力）＝ 8100、嗅覚 875、予備 325 で **9300**（従来 10450）。

## モジュール契約

### `meta.ts`

`meta_max_level.sniff` を 5 にする。

効果 getter は既存の流儀どおり 1 効果 1 関数で、`level` を引数で受ける（死亡画面が次段プレビューに `level + 1` を渡すため）。

```
meta_sniff_threshold(level) → level >= 2 ? 0.6 : 0.3
meta_sniff_path(level)      → level >= 3
meta_sniff_distance(level)  → level >= 3
meta_sniff_exit(level)      → level >= 4
meta_sniff_loot(level)      → level >= 5
```

`meta_sniff_active(ratio)` は変更しない。

価格の入口を `meta_upgrade_price(id, level)` に一本化する。`meta_upgrade_cost` は曲線そのもので、モジュール内の private にする（現在は export されており `death-screen.ts` と `meta.test.ts` が直接呼ぶ）。トラックごとの刻みを 2 か所に複製しないため。

```
meta_upgrade_price(id, level) → meta_upgrade_cost(level * (id === 'sniff' ? 2 : 1))
```

### `sniff.ts`

`sniff_result_t` を `{ angle, path_angle, dist }` に拡張する。

`path_angle` は自機起点の BFS を目標側から下り歩いて求める。計算量は O(距離) で、BFS 本体（O(4096)）に対して無視できる。そのため**段による分岐を入れず常に両方返し、どちらを使うかは `minimap.ts` が選ぶ**。フラグ引数を足すより単純で、使う予定のないオプションを増やさない方針にも合う。

自機が目標の隣にいて経路に一歩もない場合は `angle` にフォールバックする。

**目標タイルが床でも壁でも `sniff_find` はそのまま正しい。** 現在の実装は「目標の 4 近傍の床までの最小距離 + 1」を返す。喫煙所のタイルは壁（生成器が 8 を書く）だが、非常口は開通の瞬間に `entity_exit_t._render()` が `level_data` へ 1 を書いて床になる。床の目標が BFS 距離 D にあるとき、経路上の先行タイルが D−1 を持つので最小近傍 + 1 は D に一致する。距離の式に分岐は要らない。

目標リストの組み立ては呼び出し側の責務のままにする。`sniff.ts` がエンティティを知らない純粋関数であるという現在の性質を保つため。

### `minimap.ts`

消費点は 3 つに分かれる。

- 光跡: `meta_sniff_path()` で `angle` / `path_angle` を選ぶ
- 距離: `meta_sniff_distance()`
- 収入系の点灯: `meta_sniff_loot()` のとき、`entity_yani_t` と `entity_drone_t` を `minimap_explored` のガードを通さずに描く。ヤニは淡い黄（215,195,110）、清掃ドローンは淡い青（140,200,240）。**どちらも明滅させない。** 喫煙所のオレンジ（238,153,0）とは色相が近いが、明滅の有無が 1 ピクセルでも読める区別になる（明滅は行き先を意味する、という既存の規約をそのまま使う）

`state.game_running` のガードは両系統で維持する。リザルト表示中に前のランの情報が残らないため。

**嗅覚の実装が `minimap_sniff()` と `minimap_draw()` の 2 か所に分かれることを受け入れる。** 収入系は発動条件を持たないので、発動判定の早期 return を持つ `minimap_sniff()` に入れると収入系まで止まる。1 か所に寄せるほうが不自然になる。

## 表示

### 死亡画面

`upgrade_row_t` の構造は変えない。嗅覚行の `stat` を `'発動'` から `'解放'` に、`value(level)` をその段で解放されるものの名前にする。

| level | value |
| --- | --- |
| 0 | なし |
| 1 | 方向 |
| 2 | ゲージ60%以下 |
| 3 | 経路＋距離 |
| 4 | 非常口 |
| 5 | ヤニ・ドローン |

`flavor` は「利き煙草。ゲージ低下時に残り香の方向が分かる」を **「利き煙草。段ごとに嗅げるものが増える」** に差し替える。Lv5 の収入系が常時働くため、現行の文言は半分嘘になる。

**この行のセマンティクスは累積解放と噛み合っていない。** 「現在値 → 次の段の値」はスカラー向けの形で、Lv3 の表示 `経路＋距離 → 非常口` は「経路が非常口に置き換わる」と誤読される余地がある。累積の全リストは行に収まらない長さになる（`方向・60%・経路・距離`）ため、`'解放'` というラベルで読ませる側に賭ける。

### HUD

`残り香 Nm` の出現条件が Lv10 から Lv3 に下がる。HUD 側のコードは `meta_sniff_distance()` を呼ぶだけなので変更はない。

## テスト

- `meta.test.ts` — 嗅覚節を差し替える。しきい値が 2 値であること（Lv1 = 0.3、Lv2〜5 = 0.6）、4 つの解放 getter の段境界（N−1 で false、N で true）、`meta_max_level.sniff === 5` と Lv5 で `meta_buy` が false。既存の `meta_sniff_distance(10)/(9)` のケースは削除する
- `meta.test.ts` の価格 — `meta_upgrade_cost` 直呼びを `meta_upgrade_price` に置き換え、嗅覚が 15/55/135/255/415 であること、全解放の合計が 9300 であることを検証する
- `meta.test.ts` の丸め — 既存の丸めテストに嗅覚を足し、保存済みの `sniff: 10` が 5 になることを確認する
- `sniff.test.ts` — 既存 5 ケースは `angle` / `dist` の意味が変わらないため維持する。追加は 2 つ。`angle` と `path_angle` が食い違うケース（「近いのに矢印が壁を指す」状況を再現する。これが Lv3 に価値がある証明そのものである）と、自機が目標の隣にいて経路に一歩もないとき `path_angle === angle` になるケース

### テストで守れない範囲

目標リストの組み立て（残り香をどれ入れるか、`exit_open` のとき非常口を足すか）と収入系の点灯は `minimap.ts` にあり、DOM 依存のためテストしない（現状も `minimap.ts` にテストはない）。

ただし目標の**選択**ロジックは `sniff.test.ts` が既にカバーしている。非常口はリストに入った時点でただの目標の 1 つである。未検証になるのはリストへ何を入れるかという数行に限られる。この数行を切り出すには entity クラスを import する新モジュールが必要で、`sniff.ts` の「エンティティを知らない純粋関数」という性質を壊すため、テストしないほうを取る。

## 採らない案

- **ダミー判別** — 中核の問いを壊す。`docs/gameplay.md` の「足さないもの」に残す。匂いの濃さで本物を示唆する類も実質これと同じなので採らない
- **嗅覚の常時発動（生存系）** — 恒久ナビ化そのもの
- **矢印 2 本の色分け同時表示** — 64×64 のミニマップに 3px の光跡が 2 本並ぶと自機周辺が読めなくなる
- **in-world 表示（視界の縁の煙の筋）** — 5 枠に入らなかった。情報量ではなく演出の追加であり、5 段が埋まっている現状では優先度が下がる
- **既存セーブの移行** — `meta_load` が `sniff: 10` を 5 に丸める。2025 支払ったセーブが 875 相当になるが、後方互換を維持しない方針どおり移行処理は置かない
