# 喫煙所ビジュアル改善 設計書

作成日: 2026-08-20

## 目的

docs/story.md の世界観に合わせ、喫煙所を「本当のたばこの喫煙所」に見えるようにする。あわせて、ダミー喫煙所を踏んだ後に「灰皿が撤去された跡地だった」ことが見た目で分かるようにする。

前提: 新規の絵素材は Codex の画像生成で作る。

## 制約（変えないもの）

- **触れる前は本物とダミーを完全に同一の見た目にする**（gameplay.md「見分けは足で確かめるしかない」）。差が出るのは触れた後だけ
- レンダラ（`renderer.ts`）は変更しない。既存の `push_block` / `push_sprite` / `push_light` とアトラス 1 枚（`m/q2.png`、1024×16、16×16 タイル×64 枠）の範囲で表現する
- HUD・ターミナル・敵・hero 画像はスコープ外

## 新規タイル（アトラス 32〜37 番に固定）

| # | 内容 | 用途 |
| --- | --- | --- |
| 32 | 灰皿の口（砂と吸い殻） | スタンド灰皿ブロックの天面 |
| 33 | ステンレス胴体＋オレンジ帯 | スタンド灰皿ブロックの側面 |
| 34 | ボルト跡＋色あせた円形の跡 | ダミー開示後の天面 |
| 35 | 「灰皿撤去済」貼り紙 | ダミー開示後の側面 |
| 36 | 青い「喫煙所」ピクトグラム看板 | 標識スプライト |
| 37 | 煙のひとかたまり | 一服完了後の煙スプライト |

タイル番号は `entity-smoking-area.ts` に定数として持つ。

**側面タイルの番号が 8 / 9 / 17 以外であることが要件。** `push_block` は側面タイルがこの 3 つのとき高さ 16、それ以外は高さ 8 のブロックを作る。スタンド灰皿は低い方（8）で描く。

## 喫煙所の構成（触れる前: 本物・ダミー共通）

現在の `push_block(x, z, 4, 17)`（背の高い汎用ブロック）を置き換える。

- **スタンド灰皿**: `push_block(x, z, 32, 33)`。低い 8 ユニットのブロック
- **標識**: `push_sprite`（タイル 36）を灰皿の脇に立てる。6×6 ユニットでカメラに向かって傾く既存挙動のまま
- **明かり**: 既存のオレンジ点滅ライト（`push_light`）を踏襲

## 状態変化（触れた後）

| 状態 | 見た目 |
| --- | --- |
| 本物・一服完了 | 灰皿から薄い煙が上がり続ける（下記 `entity-smoke.ts`）。ライトは点滅→常灯（既存の `_done ? 0.08 : ...` の分岐をそのまま利用） |
| ダミー・踏んだ後 | ブロックを `push_block(x, z, 34, 35)` に、標識スプライトも貼り紙タイル（35）に差し替え。ライト消灯。ミニマップはオレンジ→灰色 |

### 煙: `source/entity-smoke.ts`（新規）

既存の `entity_particle_t` は重力落下＋地面バウンドの破片用で煙には使えない。上方へゆっくり漂い（重力なし・わずかな横揺れ）、約 2 秒で消える小さなエンティティを新設する。スプライトはタイル 37。

- 一服完了済みの本物の喫煙所が、`_render()` 内で一定間隔（0.5 秒程度）ごとに 1 個ずつ生成する
- `entity.ts` の不変条件（基底がサブクラスへ到達しない）は、サブクラスを自モジュールに置き喫煙所側から import する形なので破らない

### ミニマップの灰色化

`entity_smoking_area_t` に「ダミーを開示済みか」の公開読み取り（例: `get revealed_dummy(): boolean`）を追加し、`minimap.ts` が色分岐に使う。開示済みダミーは灰色、それ以外の喫煙所はオレンジのまま（本物は完了後もオレンジ）。

## Codex 画像生成パイプライン

16×16 を直接生成させると崩れるため、大きく生成して縮小する。

1. Codex に 1 モチーフ = 1 枚（512×512 程度）で 6 枚生成させる。プロンプトには「16×16 grid の pixel art」「単色背景（透過処理用のキー色）」「低彩度・既存アトラスに合わせた暗めのパレット」を指定する
2. `tools/atlas.py`（新規、`uv run --with pillow` で実行）が、生成画像を 16×16 に縮小（box フィルタ）→ 背景キー色を透過 → パレット量子化し、`m/q2.png` のタイル 32〜37 に合成する。**再生成しても同じコマンドで焼き直せる**冪等な作りにする
3. 生成元の大きい画像はリポジトリに入れない（`q2.png` に焼いた結果だけが成果物）

生成結果が 16×16 でノイズだらけになり使いものにならない場合のフォールバックは、Claude がピクセル配列を直接書く手描き。パイプライン（`tools/atlas.py`）はどちらでも共用できる。

## 検証

- 見た目は `npm run dev` の手動確認（本物とダミーが触れる前に区別不能なこと、ダミー開示後の差し替え、煙、ミニマップ灰色化）
- `entity-smoking-area.test.ts` に、開示状態の公開読み取り（`revealed_dummy`）の遷移テストを追加
- 頂点バッファへの影響: ブロック数は据え置き、増えるのはスプライト（標識 1 枚 = 6 頂点/箇所）と煙（同時 4〜5 個程度）のみで、上限 65536 頂点に対して無視できる

## 採用しなかった案

- **専用の大きいテクスチャ/デカール** — マルチテクスチャ対応などレンダラ改修が必要で、既存ドット絵と質感が浮く
- **パーティション壁で「ブース」を作る** — 部屋生成側にブース用の床確保が要り、生成器まで改修が波及する割に、灰皿＋標識だけで十分伝わる
- **本物の完了表現に灰皿タイルの差し替え** — 煙とライト常灯で十分伝わる。タイル枠の節約を優先
