# メタプログレッション（通貨「ヤニ」と恒久強化）

ラン間で持ち越すのはヤニ残高・強化レベル・ベスト深度のみで、`source/meta.ts` に置く。ラン状態（`state.ts`）と寿命が違うため分離している。`meta.ts` は `state.ts` と同じく実行時 import を一切持たない葉モジュールで、Node（Vitest）でモックなしに評価できる。

## 通貨「ヤニ」

喫煙が非合法化された世界では吸い殻そのものが闇で価値を持つ（docs/story.md）。入手は敵ドロップ（撃破ごとに 50% で 1）・床への散在（フロアあたり 1〜3）・フロア到達ボーナス（深度と同数）の 3 経路。

**死亡時も全額持ち帰り、ロストなし。** ランごとに通貨を失う設計は「損した」感覚を残すだけで、深度を伸ばす動機にはならない。

## 強化テーブル

最大レベルは肺活量・ニコチン耐性・嗅覚・火力が 10 段、予備の一本のみ 5 段。コストは `15 + 10lv + 5lv²`（15/30/55/90/135/190/255/330/415/510）で、10 段の項目 1 本が 2025、予備が 325、全解放の合計は 8425。効果値と段階は `meta.ts` が持つ。

**倍々のコスト曲線（`20 << lv`）は採らない。** 5 段までなら成立するが、10 段に伸ばすと最終段が 10240 になり、それ 1 段のために他の全項目を捨てる形になって選択が壊れる。二次式は最終段でも 510 に収まり、どの段の価格も単独では無理なく払える帯にとどまる。

ただしこれは曲線が全トラック共通であることの効果で、「価格が壊れない」以上のことは保証しない。段あたりの効果量はトラックごとに大きく違う（肺活量 +10 ゲージ/段、耐性 −4%/段、火力 −5%/段に対し、嗅覚は発動しきい値が +3.33pt/段動くだけで上限（60%）自体は動かない）。そのため嗅覚の後半の段は、価格が他トラックと横並びでも「いつ働き始めるか」を早めるだけの息の長い贅沢枠であり、他トラックと競い合う購入にはならない（上限を動かさない理由は次項）。

効果曲線は段あたり一定量の加算で、上限は次のとおり。

| 項目 | 式 | 全強化 |
| --- | --- | --- |
| 肺活量（最大ゲージ） | `100 + 10 × 段` | 200 |
| ニコチン耐性（減少係数） | `1 − 0.04 × 段` | 0.60 |
| 火力（射撃間隔係数） | `1 − 0.05 × 段` | 0.50 |
| 予備の一本（本数） | 段数そのもの | 5 本 |

射撃間隔は 基礎 0.1 秒 × 火力係数（強化） × ニコチン係数 の順に掛ける。

全強化の実効倍率は 最大ゲージ 2 倍 × 減少係数の逆数（1/0.60）で **3.33 倍**。√ 減少式と釣り合うのは深度 152 で、到達しうる深度のはるか先にある（docs/gameplay.md「減少速度が平方根である理由」）。

## 嗅覚が低ゲージ時のみである理由

恒久的な方向ナビは中核の問い（ゲージが尽きる前に喫煙所を見つけられるか）を恒久的に無効化する。そのため嗅覚は追い詰められたときだけ働く救済に限定する。「切羽詰まるほど鼻が利く」というフレーバーで離脱症状と噛み合う。

発動しきい値は残量比で `0.3 + (段 − 1) × (0.3/9)`。1 段 = 30% 以下から等間隔に緩み、10 段で 60% 以下になる。距離表示は最終段のみ。**上限を 60% に留めるのは上の理由がそのまま効くため。** 段を増やした分は「いつ働き始めるか」の細かさに配る。

しきい値を段ではなく**比率**で受けるのは、判定に使う値（`state.nicotine / state.nicotine_max`）を呼び出し側が既に持っており、`meta.ts` がニコチンの段階判定を知る必要がないため。この形にしてあるおかげで `meta.ts` は実行時 import を 1 つも持たない。

矢印は本物とダミーを区別せず、最寄り（自機からの BFS タイル距離）の「残り香」を指す。跡地にも残り香はある、という理屈で、嗅覚を積んでもダミーの緊張は残る。ダミー判別の強化は意図して置かない。BFS は 1 秒間隔で再計算する（毎フレームは過剰）。

矢印の向き自体は自機から目標への直線（ユークリッド角）で、最終段で表示する距離は BFS の経路長という、別の値を組み合わせている。そのため通路が入り組んだフロアでは、短い距離が表示されているのに矢印は壁の方向を指す、という場面が起こりうる。これは仕様通りである。嗅覚は「最寄りの残り香を指す」ものであって、そこへの経路を示すものではないため、矢印を経路方向に合わせる直しは行わない。

## 予備の一本と煙感知器

世界のルールは「一服すると煙感知器が作動し、非常口が開く」。予備の一本は**こっそり浅く吸うので感知器に届かない** — だから回復は 50% 止まりで、非常口も開かない。警報リスク（吸うと敵が寄る）案は緊急回復という主目的を濁すため見送った。

E キーはエッジ検出（非リピート keydown で 1、使用側が 0 に戻す）。押しっぱなしで毎フレーム発動させないため。

## 死亡画面（リザルト＋闇サイト）とスコア

自席の端末が闇サイトに繋がっている、という一つの理屈で全項目の購入を説明する（物資と怪しい訓練プログラム）。**リザルトと闇サイトは 1 画面である。** 死んだ直後に見る画面と強化を買う画面を分けると、記録を確認して閉じ、次にメニューを開くという 2 段の操作が毎ランに入る。同じ理屈（自席の端末）で説明できるものを 2 画面に割る理由がない。

実装は全画面 DOM の `source/death-screen.ts` で、見本は `m/result.png`。表示ロジックのうち DOM を触らない部分（死因メッセージ、体調テキスト、生存時間の書式）は `source/death-screen-model.ts` に分ける。`meta.ts` / `nicotine.ts` と同じ扱いで、Node（Vitest）でモックなしに評価できることが条件。

`death_screen_show(result, on_start)` の `result` が `null` のときは**初回起動モード**になり、記録パネルと状態パネルを出さず見出しを差し替える。初回も同じ画面を経由させるのは、前セッションの残高を降下前に使えるようにするためと、初回プレイでも操作の予告になるため。

強化行の説明文はその段までの累積効果を書き、段ごとの増分は書かない（購入判断はその 1 行しか根拠がないため）。効果の数値は `meta.ts` の getter から引き、式を画面側に書き写さない。

**この画面はターミナルの後片付けを持つ。** 表示に入る時点で進行中の表示チェーンを止め、`terminal_el` を空にして隠す。死亡画面はターミナルを使わないため、これをしないと起動時の文字や直前の通知が裏で動いたまま画面に重なって残る。

### 記録する統計

| 値 | 書き手 |
| --- | --- |
| `run_time` | `game_tick` が `game_running` 中だけ `time_elapsed` を積む（リザルト表示中は数えない） |
| `smoke_count` | 喫煙所での一服完了と、予備の一本の使用 |
| `dummy_count` | ダミーの開示。`_take_dummy` の `_done` ガードで同一個体は 1 度しか数えない |
| `death_cause` | `_receive_withdrawal_damage()` が死亡時に立てる。既定の 0 は敵による死 |

いずれも `run_start()` で 0 に戻す。

**獲得ヤニの内訳は持たない。** `run_end()` はヤニを `meta.yani` へ合算した**後**に画面を出すので、画面に出るのは合算後の残高だけである。死亡時も全額持ち帰る（上記）ので内訳は購入判断に効かず、残高が 1 つだけ出ているほうが「あと何が買えるか」を読み間違えない。

スコアは到達深度のみで、ベスト深度だけ保存する。

## `run_end()` の単一呼び出し不変条件

一次防御は `entity_player_t._kill()` の `_dead` ガード（`entity-spider.ts` / `entity-sentry.ts` の `_kill()` と同じ形）で、これだけでも `_kill()` の再入は止まり `run_end()` は 2 度呼ばれない。`run_end()` 自身が持つ `state.game_running` ガードは二次防御で、こちらも単独で同じ再入を止められるが、本来の役目は `run_end()` を、`entity-exit` / `entity-smoking-area` / `entity-player` が実行条件として読む同フラグの唯一の書き手であり続けさせること。危険自体はまだ現実にある: `_receive_withdrawal_damage()` は `_receive_damage()` の 2 秒無敵を通さず、死んだ自機は衝突ループの除去（フレーム末尾）前まで 2 体目として接触されうるため、2 つのガードが同時に外れれば、ニコチン切れの死と同じフレームの敵接触で `_kill()` が 2 度走り、ヤニが二重に加算されたまま保存される。

## 保存

localStorage に 1 オブジェクト（キー `takagi_meta`）。使えない環境では try/catch でメモリ内フォールバックし、`meta.persistent = false` を見て死亡画面が「このセッション限り」と警告する。読み込み時は範囲外の値を最大レベルに丸め、壊れた JSON は捨てて初期値で始める。
